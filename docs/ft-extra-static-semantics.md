## 六字段、显式 0 和显式 1 的关系

应区分文件中第七词是否存在、读入时的整数参数、原对象内的单字节标志，以及本项目的 `optional<int> extra`。四者不能混为一个值。

| 静态位置 | 已独立核对的规则 |
| --- | --- |
| OVR `0x3d639 + 0x0901` | 六次整数读取后检查行尾；局部第七参数在 `+0x090f..0x0911` 先清零，未到行尾才在 `+0x0961..0x0966` 读第七整数。 |
| 同块 `+0x09b6..0x09cb` | 顺序压入 x1、y1、x2、y2、宽、层、第七参数，调用常驻 `12fe:12e3`。因此被调用者 `BP+6` 对应第七参数。 |
| 常驻 `12fe:1384..1393` | 将第七参数与**整数 1**比较；恰等于 1 写对象 `+0x0b = 1`，否则写 0。这是等于 1 判断，不是非零判断。 |
| OVR `0x41cd4 + 0x06fd` | 保存同一走线对象的四坐标、`+8` 宽、`+9` 层；在 `+0x087e..0x08b6` 检查 `+0x0b`，非零写第七整数 1，零写 0，随后结束行。 |
| 同块 `+0x103c` | 顶层保存遍历自由走线表并调用 `+0x06fd`；`+0x0a49` 对元件走线列表也调用此函数，标签由外层状态选择。 |

在数值读取成功、端点非退化、分配成功及调用路径成立的前提下，可用以下自主数学模型描述：

`参数 t = 文件第七整数（缺失则为 0）；对象标志 b = [t == 1]；保存第七整数 s = [b != 0]。`

该模型限定为送达创建函数的 16 位参数，不定义超范围文本被 Pascal 整数读取器怎样处理。32 位整数、溢出、非法字符不能按模 65536 截断后宣称兼容。

| 文件情况 | 创建后的 `+0x0b` | 所核对保存路径的第七词 | 本项目建议 |
| --- | ---: | ---: | --- |
| 缺失 | 0 | 显式 0 | 保留“缺失”这一原始布局事实 |
| 显式 0 | 0 | 显式 0 | 保留原词及存在性 |
| 显式 1 | 1 | 显式 1 | 保留原词，不能解释成网络或平面编号 |
| 其他可送达的 16 位整数 | 0 | 显式 0 | 非规范值继续视为未知；不得静默采用原软件归一化 |

由此可确定：**在这条原程序读入链中，缺失与显式 0 创建相同标志；原对象中没有为该字段另存“原词存在性”的成员，所核对保存函数也不按存在性选择六／七字段。** 它会输出第七词；这不意味着本项目可以删除 `optional` 区别或重写旧词。原软件的规范化保存与本项目已有的原字节保留契约不同。

本结论是原指令静态语义，不是六字段样例实际加载、另存、重开的运行证据。也没有证明所有导出模式、所有历史格式均走同一保存入口。

## 标志的已证消费者与未证电气含义

`+0x0b` 至少参与预布走线的路由处理；当前证据支持把它描述为**影响预布走线处理的标志**。下表保留事实范围，不把候选偏移上的同名字段全部归为走线。

| 消费者 | 静态依据 | 能说明什么 |
| --- | --- | --- |
| 预布走线平滑设置 | OVR `0x1e0bf + 0x0512` 以菜单号 `0x95` 调选择器，把非零返回写入 `DS:f7e8`；MNU 的 MENUS 段第 149 项是 `ROUTE_USERTRACKS`，标题 `SMOOTH PRE_ROUTES`，选项依次为 On、Off。`+0x055f` 的设置面板也按此值选择文字。 | 在固定样本中，1／2 对应这项菜单的 On／Off；不能从常量名称猜含义。 |
| 同宽端点整理 | OVR `0x299bd + 0x031b` 的 `+0x03e9..0x0409`，以及 `+0x045c` 的 `+0x052a..0x054a`，先比较走线宽 `+8` 与 `DS:375c`；标志非零且 `DS:f7e8 == 2` 时跳过后面的端点修改。 | 对这些路径，Off 会保护标志为 1 的走线免于该整理；标志为 0 不因这一条件被跳过。不是全部编辑操作的“锁定”证明。 |
| 另一预布走线整理遍历 | OVR `0x26d6b + 0x2685` 在 `+0x275d..0x2780` 检查同宽及标志；标志非零只有 `DS:f7e8 == 1` 才继续。OVR `0x2a4e3 + 0x0669` 的列表检查使用相同 Off 拒绝条件。 | 给出独立的设置→对象标志→整理分支对应，不能据此声称整套路由或 DRC 已恢复。 |
| 选定的交互构造／复制路径 | OVR `0x7e2b + 0x2932` 在 `+0x2b03..0x2b07` 传入 1，并在 `+0x2b20` 再写标志 1；OVR `0x19da7 + 0x00f8` 的复制路径在 `+0x01ae..0x01b2` 也明确传入 1。 | 该标志不是仅由文件存在性产生；复制也可把新对象置为 1。不能用它追溯原文件作者或精确生成历史。 |
| 选定的自动几何生成路径 | 常驻 `08fe:13d2` 在 `1633..1636` 传入 0，并于 `164c` 写标志 0；调用者包括多个路由覆盖块。 | 固定程序内部至少存在两种构造取值，不能给所有“新建”统一猜一个缺省。完整命令对应仍需进一步核定。 |
| 走线绘制包装 | 常驻 `1964:5af9..5c0a` 向 `1964:20ef` 传四坐标、`+8` 宽，并按状态传 `+9` 层／颜色；读取 `+0x0a` 选择状态，不读取 `+0x0b`。 | 这一个包装中该标志不改变传下去的走线几何。不能外推其他绘图、生产输出或电气消费者均无影响。 |

这里的标志不应误认成紧邻的 `+0x0a`：创建器把 `+0x0a` 清零，绘制及复制路径又把它作为选择／工作状态使用；原文件第七词明确落在 `+0x0b`。相同 `+0x0b` 偏移在焊盘、元件等其他类型上具有不同意义，不能靠全局偏移搜索直接建立跨类型解释。

**尚未证明该标志对网络归属、9／10 负片平面、实际铜接触、完整 DRC、全部移动／删除／撤销／重布及生产输出均无影响。** 它不是现已恢复的网络编号或平面连接枚举；目前也没有充分证据给它定义电气无影响的全局契约。既有[层／孔／平面问题](exploration-backlog.md#ex-022)和[完整 DRC 问题](exploration-backlog.md#ex-024)继续保留。

- 铜层分析继续对**存在 extra 的铜层走线，包括 0 和 1**保留覆盖不完整；这是一条尚未被完整消费者证据解除的工程保守策略。缺失与 0 的原读入等价性本身不足以修改该策略。
- 非铜层 extra 仍只按现有规则不影响铜几何覆盖；不从预布走线分支外推全部层的电气语义。
