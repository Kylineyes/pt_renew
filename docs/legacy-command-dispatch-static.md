## 录制开始、结束与递归截断

<a id="macro-recording"></a>

主菜单 Setup → Keys 的静态入口为 `1000:04e0` → 原始 `0068:0025` → Setup 块 OVR `0x4+2625`；其第 4 项在块内 `267a` 调用原始 `0250:0025`，映射到 `K+30e8`。KEY 菜单 102 的第 9 项 Record 在 `K+316b` 调用 `K+2c9d`。这里有菜单内容、实际分支和覆盖槽位三种依据。

`K+2c9d` 在已录制时返回，宏数达到 48 时给出对应消息；之后询问并检查非空名称、重名和触发键冲突。成功后复制名称到 `68bc`，长度清零，触发码存 `68c7`，置 `68ba=1`，并把一个 Esc 压入公共输入队列。**该 Esc 是开始录制后的排队输入，不是执行完成证明**；它是否随后进入录制数据，取决于下一次取键的实际上下文及跳过条件。

录制取键路径的具体规则：

1. `324e:0ae8` 将队列码 `0xf5` 视为结束标记。KEY 解析器的 `K+1aaf`～`1abb` 把文本 `<^END>` 转成 `0xf5`；反向格式化在 `K+0e0a` 使用同一个文本，故静态名称为 **Ctrl+End**。宿主是否交付它仍未验证。
2. 长度大于零时，先将 `6932` 加一，再把 `68bc` 起的 `0x72` 字节复制到宏表的新记录；空录制不新增定义。随后清 `68ba`。提交发生在后续通用追加分支之前，因此结束标记不在刚提交定义中；不要把临时缓冲之后可能追加的字节算进已提交宏。
3. 普通录制码在长度小于 100 时追加；达到 100 后不再追加，取键路径仍继续返回输入，未见此分支自动停止录制或自动提交。
4. 录制记录的是公共取键层的字符／扩展码，不是 Qt 命令 ID、图元身份、撤销记录，也没有在这里捕获一份鼠标轨迹。输入收集层能将部分指针按钮映射为 Enter／Esc，但这不能恢复几何拖动全过程。

展开器 `324e:0965` 的调用树上，深度从 0 开始，入口先检查 `<10` 再递增；最多有 10 层活动展开。宏体某字节若匹配已装载宏的触发码，会递归调用；匹配后会标为已处理，即便递归在深度门返回，也不会把原触发字节重新入队。故环／自引用可以导致分支被截断，**不是有错误返回的原子失败，也没有回滚已入队前缀**。展开前、遍历每字节时和普通入队前另查队列满，队列满同样可能留下部分前缀。

宏体嵌套匹配本身不再检查 `68b9`，而由外层触发处的允许门进入；不能假设每一层都有独立的启停门。外层 `324e:0a30` 在 `0b80` 调用展开后，也没有清除输出指针中原先的触发码或立即再出队；本次调用仍返回触发码，宏体留在队列供后续调用消费。触发码本身是否被上层忽略或另作解释也是上下文条件，不能把展开模型简化成原地替换。

展开递归和后续消费队列是两个阶段：这些按键随后仍由当时的菜单、文字询问和活动工具解释。固定 KEY 的 46 个定义中，F3 为 Esc、Esc、P、T、Enter；它不等于在任意上下文执行一个原子“放走线”。固定 `<^U>` 宏为 Esc、Esc、U、E，后文说明其额外未知。

证据：`E/recording-controls.txt`、`recording-export.txt`、`tokens.txt`；`S/overlay-key.json` 的 `2c9d`、`30e8` 及 `S/resident-review.json` 的取键／展开函数。96 项核验实际检查了记录尺寸、100／48 上限、终止码、深度及固定 KEY 序列。

## Repeat 保存的是放置模板

<a id="repeat-placement"></a>

主菜单第 14 项在 `1000:04d4`（EXE `0x42b4`）调用原始 `0206:0025`；描述符在 EXE `0x5e40`，槽位 1，目标 `P+3143`（OVR `0xaf6e`）。MNU 第 193 项为 `REPEAT PLACEMENT`，四行分别为 Execute Repeat、Count Default、X-Offset、Y-Offset。**“重复上一操作”不足以准确表达这套行为。**

`P+3143` 将当前次数 `DS:d4e8`、X 偏移 `d4e4`、Y 偏移 `d4e6`填入显示缓冲，调用选择器后分别进入 `30af`、`2f9d`、`2fe5`、`304a`。执行路径 `P+30af`：

- 先调用块内 `P+000f` 辅助例程，本次未解释它的完整副作用；从默认次数取得局部值，经菜单 196 再询问。
- Esc 直接返回；次数大于 1000 截至 1000，小于 1 不执行；合法次数写回默认值。次数不为 1 时，还须菜单 194 返回 Yes（2），才进入循环。
- 循环每次调用 `P+2058`，该函数在 `DS:7107` 非零时返回，否则按 `DS:d58c` 分派到不同图元处理函数。它不取“上一条菜单序号”重放，也不调用公共宏展开器。
- 默认次数编辑同样钳制到 1～1000；X/Y 偏移编辑钳制到 −10000～10000。偏移询问和创建计算受 `DS:70ec` 分支控制；本次保留其数值变换分支，不把它未经独立验证就命名为特定单位模式。

| `DS:d58c` | 模板／来源 | Repeat 处理入口 | 依据与范围 |
| ---: | --- | --- | --- |
| 1 | Arc，`DS:d532` | `P+1d1e` | Place 菜单 Arc 路径及模板写回；绘制 `2964:54cb` |
| 2 | Fill，`DS:d522` | `P+1ad3` | Place Fill 分支；模板两角坐标与层；绘制 `2964:543f` |
| 3 | Pad，`DS:d4f8` | `P+1803` | Place Pad 成功路径 `P+278e`～`27a1` 复制对象并记类型 3 |
| 4 | Component，远指针 `DS:d4f4` | `P+03a4` | 对组件节点及子对象逐项处理；没有把这条较长路径的命名／网络副作用宣布为完整恢复 |
| 5 | String，`DS:d554` | `P+1eb6` | Place String 分支及文字绘制 `2964:53a3`；不重复验证字形 |

| 7 | Via，`DS:d514` | `P+198a` | Place Via `P+2e27`，成功后 `P+2f65` 记类型 7 |

这些类型编号是本固定样本的内部状态，不是 PCB 文本记录的类型编号；与下文删除栈编号也不同。External Plane 虽在 Place 菜单里，不能因此扩展为 Repeat 第八种模板。

以 Track 的 `DS:70ec==0` 分支为明确例子：`P+1794`～`17c4` 读取模板的两个端点，分别加 `d4e4`／`d4e6`，取保存的属性字节，调用原始 `12fe:12e3`（分析地址 `22fe:12e3`）创建；`P+17ec`～`17fa` 再将返回节点的 `0x11` 字节复制回 `DS:d542`。正常返回有效节点时，下轮使用新坐标，因此第 n 次成功重复相对初始模板累计 n 倍偏移，而非所有副本落在同一位置。Fill、Arc、Pad、Via、String 也各有模板更新路径，但不能由此声称所有变体的副作用相同。

该 Track 路径在空返回时只跳过绘制，随后仍走节点复制；本轮没有验证分配器的实际失败契约，**不能据静态路径宣称空返回安全，也不能把它直接升级为已复现缺陷**。坐标辅助 `P+032e` 在两个坐标加偏移后检查正数及 `0x7d00` 上界；其中先做 16 位加法再扩展，不能把这个实现当成新版通用无溢出几何判据。

证据：`E/repeat-controls.txt`、`repeat-worker-cfg.txt`、`repeat-handlers-cfg.txt`、`repeat-component-cfg.txt`、`track-placement-cfg.txt`、`repeat-template-proof.txt`。部分最早的线性反汇编起点误落指令内部、Component 初次范围过窄；最终以入口可达解码及 `validation-summary.json` 为准，不采用那些失败输出中的伪指令。

## Un-Delete 恢复对象链，不是通用撤销历史

<a id="undelete-stack"></a>

主菜单第 16 项在 `1000:04ec`（EXE `0x42cc`）调用原始 `007c:002f`，槽位 3，目标 `I+1cbb`（OVR `0x4680`）。固定菜单没有一个另列 Execute 的 Un-Delete 子菜单：MNU 第 245 项是 `UN-DELETE COUNT`。

`I+1cbb` 将数量初始设为 1，通过常驻 `324e:252b` 询问；Esc 或小于 1 返回，大于 `DS:f7e2` 则截到该计数。执行前置 `DS:c337=1`，循环调用原始 `12fe:5d67`，即分析地址 `22fe:5d67`（EXE `0x1cb27`）。因此这个数量首先是删除记录的数量，不能未经批量操作分组证据称为“用户操作次数”。

`22fe:5d67` 在计数为零时返回；否则读取 `DS:(e459+f7e2)` 的类型字节，从相应删除链头取对象并接回模型，最后在 `609f` 将 `f7e2` 减一。恢复顺序由全局类型栈决定，各类链维护该类被删对象，跨类型顺序不能单靠其中一条链恢复。

| 删除类型 | 删除链头 | 节点的下一项位置 | 恢复路径中识别的对象 |
| ---: | --- | ---: | --- |
| 0 | `DS:e432`（组件远指针） | `+68` | Component，接回 `DS:9a44` 组件链，调用绘制 `2964:6730` |
| 1 | `DS:e442`（5 字节链描述） | `+0a` | Arc，重新接入后调用 `2964:54cb` |
| 2 | `DS:e43c` | `+0a` | Fill，绘制 `2964:543f` |
| 3 | `DS:e44e` | `+32` | String，绘制 `2964:53a3` |
| 4 | `DS:e436` | `+0c` | Track，绘制 `2964:5af9` |
| 5 | `DS:e448` | `+08` | Via，绘制 `2964:5de3` |
| 6 | `DS:e454` | `+16` | Pad，绘制 `2964:5c4d` |

六种非组件路径先把 5 字节链描述复制到局部变量，经 `39f7:0342` 取节点，再把节点内的下一项描述写回删除链头，调用各类重新接入函数；不是重新执行先前的 Delete 键序列。组件路径则使用真实远指针和 `+68` 链接，不能把它与 5 字节描述混为一种裸指针。

对应入栈例程 `22fe:5a53`、`5acb`、`5b43`、`5bbb`、`5c33`、`5cab`、`5d23` 都在 `f7e2<5000` 时增加计数并保存类型；类型 4 的 `5a53` 同时把 Track 接到 `e436` 链头。这给出后进先出的静态结构及本样本 5000 条记录的保护门；没有恢复容量已满后所有调用方如何处置对象，也没有证明 5000 是文件格式上限。

固定 KEY 的 `UNDELETE` 名称不能补足响应证据：它展开 Esc、Esc、U、E，而 `U` 的可达调用是数量询问 `324e:252b`，不是有 Execute 行的菜单。附带 `E` 会如何被询问层处理、是否仍等待 Enter、在哪些上下文有效，本轮未实际验证；不能把宏名翻译成“Ctrl+U 已经完成恢复”。

证据：`E/undelete-worker.txt`、`undelete-worker-tail.txt`、`deletion-stack-cfg.txt`、`deletion-push.txt`、`integer-query.txt`，以及覆盖映射器对 `007c:002f` 的实际槽位解析。

## 对新版命令与后续验收的约束

<a id="remaining-runtime"></a>

| 消费者 | 静态阶段可采用的区分 | 仍不能宣称 |
| --- | --- | --- |
| 统一命令目录 | 宏是有上下文的输入序列；Repeat 需放置模板、偏移、次数及当前可用条件；Un-Delete 有独立删除记录来源 | 现有 `edit.repeat`、`edit.undelete` 已实现或与原程序等价 |
