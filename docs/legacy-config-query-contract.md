## 调用实参与影响边界

本节继续[EX-005](exploration-backlog.md#ex-005)，区分属性读取、输出与shell环境更新。固定目标为 `C:/Users/rikideng/scoop/apps/dosbox-x/2026.10.01/dosbox-x.exe`，SHA-256 始终为 `a82adcfa7af2784566cfeff74c077cefed08505396db2948b7e6aa7d4cee0832`，首选基址为 `0x140000000`。以下无前缀短地址表示 RVA，例如 `a667c0` 表示静态 VA `0x140a667c0`；字面、全局和虚表用完整 VA，不当作实际运行地址。

GET 命中当前属性且返回串不等于 `PROP_NOT_EXIST` 时，普通路径为：

```text
a6f943：查 Section
  → a6f9ab：Section 首槽，sdl 为 a8b630
  → Property+40 的当前 Value，经 a876e0 转文本
  → a6fd7e：CONFIG 对象输出虚槽 +10，格式 "%s\n"
  → a6fd9b：a667c0(shell, "CONFIG", 当前值文本)
  → 析构临时文本 → a6de2b 清理 → a6de87 返回
```

| `a6fd9b` 的 Win64 实参 | 原代码正证及含义 |
| --- | --- |
| RCX | `a6fd94` 读取全局 `0x144b55578` 中的对象指针，指令为 `48 8b 0d dd 57 0e 04`。此前[发布门类型](legacy-dosbox-configuration.md#autoexec-publication-pointer)已将它绑定为 DOS_Shell／DOS_ConfigShell 指针；这里没有非空检查，正常路径以对象有效为前提。 |
| RDX | `a6fd8d` 的 `48 8d 15 68 c0 aa 00` 取 `0x14151bdfc`，原 bytes 为 `43 4f 4e 46 49 47 00`，即 `CONFIG`。 |
| R8 | `a6fd85` 从本次返回的临时字符串取得字符指针，`a6fd8a` 的 `4c 8b c0` 将它放进 R8。不是属性对象、配置文件名或节名。 |
| 返回使用 | `a6fd9b` 的 `e8 20 6a ff ff` 调到 `a667c0`；返回后仅 NOP、临时串析构和跳转清理，没有测试 AL／EAX。 |

`a667c0` 原诊断字面明确包含 `Program::SetEnv()`；它在入口把 R8 保存为值指针、RDX 保存为名称指针。`ab2e29` 的 DOS_Shell 构造先调用公共构造 `a64ac0`，公共构造在 `a64bb7/19` 保存段基址到一个包装对象，再将包装指针写到 shell 的 `+38`。SetEnv 从 `[RCX+38]` 取包装，再读其 DWORD 基址的 `+2c` WORD，作为 DOS PSP 的环境段；这也与原“无法定位环境块”诊断一致。

环境段为 `s` 时，正常算术得到环境起点 `B=s<<4`，从 `(s-1)<<4` 的 `+3` WORD 读取 MCB 段落数 `p`，末端为 `E=B+(p<<4)`。这里只按有效 PSP／MCB、普通 RAM 映射、无整数回绕或并发改写的 DOS 状态解释，不验证现场结构。

| 影响对象 | 该站点可证明的影响 |
| --- | --- |
| DOS shell 环境 | **会尝试改写。** 名称先复制到自有临时串并逐字节转为大写；环境中按 `NAME=` 边界匹配。已有匹配条目可被移除，后续内容前移；值非空时在环境尾写入 `CONFIG=文本\0\0`。这是 shell 所保存 PSP 的环境，不能改称 CONFIG 子程序自己的瞬时环境。 |
| 配置 Property | 命中的 getter 从 `Property+40` 取 Value，向返回临时文本写结果；SetEnv 只接 shell／名称字符指针／值字符指针。本条正常局部路径未调用 Property setter 或将查询值写回 Property，不能把这点推广到其它 CONFIG 分支或初始化回调。 |
| 宿主配置／板图文件 | 所核正常 RAM 环境写路径没有文件路径、配置保存或 Property 写入接口。它经客体内存页表直接写 byte，或调用内存处理器虚槽 `+20`；并非宿主配置文件写入函数。这里不证明全部内存处理器实现及异常日志后端永远无宿主 I/O。 |
| 输出与日志 | 命令整体会写 DOS 句柄 1；实际对象可由重定向决定，不能据 GET 名称承诺不写宿主文件。SetEnv 容量失败会调用日志及环境转储，日志后端也不在本次展开范围。 |
| 命令内部临时状态 | 参数列表被消费／复制，临时字符串、流对象和输出标志有分配／写入／清理。这些不属于配置 Property 写回，也使“整条命令零内存副作用”不成立。 |

关键客体写入正证：`a66b7e` 的 `44 88 04 08` 在移除条目时前移后续 bytes；`a66c77` 的 `42 88 14 08` 写名称；`a66cbd` 的 `c6 04 01 3d` 写 `=`；`a66d25` 写值；`a66d67`、`a66d9e` 分别写两个 NUL。每一类 RAM 直写均有对应的页处理器 `+20` 回退边，不能将栈上临时串的写入误当 Property 写入。

## SetEnv 与输出的局部成功／失败

设名称长度为 `n`、非空值长度为 `v`，SetEnv 在 `a6698e..95` 计算所需尾部空间 `need=n+v+3`，包括 `=` 与两个 NUL。对于 `CONFIG`，若文本为 `false`，need 为 14；若为 `true`，need 为 13。这里是条件算术，不把流输出文本无条件硬编码为这两个词。

| 局部条件 | 普通返回与可见行为 |
| --- | --- |
| DOS 内核禁用标志 `0x1416a20a2` 非零 | `a667ff..16` 记录原 `Program::SetEnv()` 禁用诊断，AL=0 返回。 |
| PSP 环境段为 0 | `a66871..84` 记录无法定位环境块，AL=0 返回。 |
| 找到同名条目，非空值的条目起点加 need 大于 E | `a66a53..60` 跳 replacement 容量错误；日志后调用 `a65f90`，BL=0，再归并返回 EAX=0。 |
| 移除旧条目／扫描到尾后，追加位置加 need 大于 E | `a66bd5..be1` 不满足 `<=`，走 addition 容量错误，经同一失败尾返回 0。 |
| 追加空间足够且各辅助正常返回 | 顺序写名称、等号、值与两个 NUL；`a66dd5` 置 BL=1，`a66de0` 以 `movzx eax,bl` 返回 1。值为空的通用删除成功边也到此，但两键正常非空文本查询不依赖空值边。 |

**失败不是原子回滚契约。** replacement 检查在删除当前旧条目前；addition 检查在已有条目移除／前移之后。因而可以先删除旧 CONFIG，再在 addition 容量检查失败；本路径没有恢复旧环境的代码。一个仅说明分支可兼容的算术例子是容量 64、旧 CONFIG 条目占 9、其它条目占 54、最终空条目占 1，初始合计 64；新文本需要 14，旧起点的 `0+14<=64` 可过，移除后尾位置 54 的 `54+14>64` 可失败。这个例子不是目标运行、故障注入或用户环境观察，亦不声称具体历史环境曾满足它。

`a65f90` 的原字面为 `DebugDumpEnv()`，并用 `...%s` 将逐项读取的环境字符串送到日志函数；容量错误不只是一个静默布尔值。若数据结构损坏、扫描缺 NUL、触发断言／异常或页处理器有额外行为，本表不提供完整恢复／返回保证。调用方也没有检查这些局部布尔结果，因此不能从 CONFIG 普通返回推断 SetEnv 成功，更不能推出 DOS ERRORLEVEL 的统一含义。

输出虚槽已由 CONFIG 构造写入的 `0x14151cbc0` 原表绑定：`+8` 为 `a6dbf0`，`+10` 为 `a650c0`。此输出函数跨五段连续 pdata 范围，不能把首段在 `a65114` 结束误判成函数已经返回。正常输出路径先调用格式辅助 `19a320`，忽略其返回值；后者可将负结果规范为 -1，但本轮没有展开整个 CRT。

输出随后逐字符／必要 CR 调用 `46a640`，实参为句柄 1、缓冲地址、WORD 数量地址及 R9=0。该函数解析当前 PSP 的句柄并调用文件对象虚槽 `+10`，把实际数量回填；非法／缺失／未打开句柄有设置错误 6、AL=0 的本地分支。输出包装在各调用后不检查 AL 或回填数量，也无“输出失败则跳过 SetEnv”的条件边。因而：

- 输出辅助普通返回，即使底层返回 false／短写，控制流仍能到 SetEnv；若抛异常、不返回或发生其它非普通控制转移，则不保证到达。
- 属性转文本、输出送达、环境更新和整个命令返回是四个不同判断，不能互相代替。
- 已见 bool 转文本分支在 `a87762` 设置 `0x4000`（boolalpha）后取 Value `+4`，调用流插入；该插入依赖流状态与 locale facet。只有流正常、相应 locale 名称及格式行为符合时，才把文本解释成常见 `false`／`true`。本轮不穷举 locale／全部 CRT。

## 两键的最小查询契约

下列仅是 **DOS shell 中已解析为内建 CONFIG 调用时的候选语法**，不是宿主 EXE 命令行开关，也不是已经执行的查询回执：

```text
CONFIG -get sdl fulldouble
CONFIG -get sdl waitonerror
```

每次独立调用；命令尾只用所示小写 ASCII、一个空格分隔、不加引号、逗号、等号、额外参数或重定向。要求 shell 正常传递该命令尾到 CONFIG 构造和命令模型；命令查找／外层 shell 全部预处理不在本次展开。该受限形式有以下正证，不要求恢复全部语法组合：

1. CONFIG 构造 `a71d64→a64ac0`，后者在 `a64d2a..3a` 把客体命令尾传给 `a8ff00` 构造；在已取得该尾的条件下，`a8ff00` 的非引号普通分支以 byte `20` 分隔词元，`a9008c` 发布前一词元，`a900dc..f5` 发布末词元。`a912e0` 复制词元进链表节点。上述短 ASCII 尾低于该公共构造命令尾长度截取边界，不依赖长尾或引号行为。
2. `a8fa70` 按参数表识别精确 `-get`；`0x14151cb30` 指向原 `0x14151b9b4`，相对表基 `0x14151ca80` 为第 22 项。`a8fb2d` 返回类别 index+2；两个非开关词元复制进每项 `0x20` 字节的向量，表相关项 case24 的 DWORD `22 f8 a6 00` 指向 `a6f822`。
3. 分支仍会先以首词元做辅助属性查找 `a8d670`，并查首词元内 byte `20`。本最小形式的首词元正是无空格 `sdl`；即使前一辅助未找到属性，搜索空间返回 -1 也在 `a6f870` 直接去 `a6f904`，绕过单串再拆分／逗号特殊逻辑。这里不是要求将两个参数预先合成一个带空格字符串。
4. `a6f904..91e` 用 `(end-begin)>>5` 取向量项数，减 1 后要求等于 1，故恰为两个查询参数；单参数走另一分支，更多参数走语法错误。本契约不使用这些分支。
5. 第一个向量元素转为独立节名串，交 `a8d5f0`；第二个元素在 `+20`，转属性名交 Section 首槽。两键的 `sdl`／Prop_bool 注册及初值继续引用[已有类型证据](legacy-dosbox-configuration.md#ex005-witness-key-binding)，本报告不复制其历史正文。

在正常已初始化对象、两个名称确实存在、getter／格式转换／输出各辅助普通返回的前提下，这条局部路径读的是**查询时 Property 当前值**，随后尝试更新同一个 shell 的 `CONFIG`。连续查询会复用并可能覆盖该环境变量；后续消费者不能把它当两键各自的独立持久快照。即使输出符合构造初值，也不能证明值来自真实用户源，见[既有见证键限制](legacy-dosbox-configuration.md#ex005-witness-key-binding)。

未来实际验收至少须分别保留命令原文、两键各自输出、固定 PE／运行上下文及必要的输出送达证据；不得用打印文本或普通返回代替 SetEnv 成功回执。本报告没有给出现场执行授权、见证键选定、用户根隔离或目录 API／阶段 Host I/O 的能力通过结论。
