# DOS 覆盖模块映射与文字研究入口

本次是 0.9.0 之后的研究工具增量，开发分支 `feat/legacy-text-evidence`；桌面应用版本保持 0.9.0。新增只读工具将主 EXE 的覆盖入口与外置代码关联，为进一步定位原文字绘制建立可复用依据；尚未恢复字形。

## 覆盖描述符布局

`PT.EXE` 的 MZ 文件头长 `0x3de0`。在装入映像的 16 字节边界上，识别到 22 个描述符。以下为本地结构核对结果，不宣称适用于所有 Turbo Pascal 版本：

| 相对描述符偏移 | 类型 | 当前解读 |
| --- | --- | --- |
| `+0x00` | 4 字节 | `CD 3F 00 00` 标识 |
| `+0x04` | u32 小端 | 外置 OVR 代码块文件偏移 |
| `+0x08` | u16 | 代码块字节数 |
| `+0x0a` | u16 | 代码块之后的段重定位表字节数，必须为偶数 |
| `+0x0c` | u16 | 五字节入口槽位数量 |
| `+0x0e` | u16 | 前一个描述符相对 MZ 映像的段值，首项为 0 |
| `+0x10..0x1f` | 16 字节 | 本地样例为零；非零变体拒绝 |
| `+0x20` 起 | 每槽 5 字节 | `CD 3F`、u16 目标偏移、零字节；`FFFF` 是无有效目标的保留槽 |

OVR 首四字节为 `TPOV`，之后每块按代码、u16 段重定位偏移表连续排列。入口目标必须处于所属代码范围，重定位的两字节目标也必须处于代码内。工具检查入口表、描述符重叠、前驱链、连续范围和文件末尾，遇到未知/损坏结构整体返回错误，不输出伪完整映射。

第一描述符在 EXE 文件偏移 `0x4460`，对应 OVR `0x4`，代码 `0x26cf` 字节，重定位表 `0x2f2` 字节，57 个槽位。第二代码块从 `0x29c5` 开始，恰好等于第一代码块及重定位表的末尾。22 块按同一规则覆盖至 OVR 的最后一个字节，没有空洞或尾部遗留。

真实输入计数：**702 个槽位、664 个有效入口、38 个 FFFF 槽位、258568 个代码字节、8001 条段重定位**。入口数量不是函数总数，也不代表已恢复函数语义。

## 定向调用候选

对每个段重定位位置，仅当其前三字节为 `9A` 时读取立即数形式的远调用候选。若目标段对应描述符，目标偏移符合 `0x20 + 5×槽号`，则映射到 OVR 代码偏移；否则在主程序映像范围内给出常驻候选，无法确认的目标明确保留未知。

本地样例得到 20 个覆盖入口调用候选和 7981 个常驻调用候选，当前规则下没有未解析项。**这是字节模式与重定位的关联，不是已确认的反汇编控制流图**：代码块中仍可能夹有数据，未证明指令可达性，也未覆盖间接调用。工具不应用重定位、不修补 EXE、不生成可执行的拼接镜像。

Ghidra 定向导出确认常驻 `2964:5af9` 中有读取几何坐标并调用 `2964:20ef` 的路径，`2964:54cb` 中有按圆弧象限及线宽调用 `2964:236b` 的路径（地址按既有 Ghidra 基段 `0x1000` 表示）。它们可作为后续绘图研究锚点；尚未据此确认文字笔画表、字距和镜像细节。

## 图形驱动证据边界

`GRAPH.DRV` 文件开头是 23 个间隔三字节的近跳转入口，`0x45` 起有 `VGA 640x480` 标识。定向 16 位反汇编显示 `0x7d` 入口使用 BIOS `INT 10h` 切到模式 `0x12`，`0x83` 使用模式 3；另有对 `A000` 显存和 `3ce` VGA 端口的操作，`0xb2c` 入口按坐标读取像素平面。最后一个非零字节位于 `0xb78`，后续是零填充。

这些证据将驱动定位为底层 VGA 绘制接口，但不足以证明字体只能位于 EXE 或 OVR，更不能把任意低值字节表当作字形。原始格式探测把没有文件头的 DRV/OVR 默认显示成 64 位数据，因此反汇编显式指定 `x86/16`；不能使用探测默认值推断架构。

## 使用与验证

工具只用 Python 标准库，不是桌面程序运行依赖：

```powershell
python tools/inspect_legacy_overlays.py 'D:/软件/PT.EXE' 'D:/软件/TRAXEDIT.OVR'
python tools/inspect_legacy_overlays.py 'D:/软件/PT.EXE' 'D:/软件/TRAXEDIT.OVR' --detail full
python -m unittest discover -s tests -p test_legacy_overlays.py
```

默认 JSON 摘要输出布局、摘要、计数和每块范围；`full` 增加槽位、重定位位置及直接远调用候选，不包含代码字节或字体。成功退出码 0 仅说明输入通过当前结构检查；错误返回 JSON `error` 和退出码 1。单文件最多读取 16 MiB，MZ 含额外尾部数据、未知描述符字段或不连续 OVR 均拒绝。

16 项独立合成测试覆盖零偏移有效入口、FFFF 槽、前驱链、文件头/尺寸/入口/重定位越界、重复重定位、损坏/重叠结构、摘要压缩、已映射/未知/禁用调用、CLI 错误及只读输入不变。CMake 在找到 Python3 时将该测试加入 CTest；找不到时明确提示跳过，Qt 构建不依赖 Python。

最终 Debug、Release 构建及 CTest 均通过八组检查：既有 QtTest 各 232 项，加上覆盖工具的 16 项 Python 测试，全部零失败。已通过命令行实际运行工具并核对上述真实输入计数；99 个原始文件 SHA-256 与既有基线全部一致，Git 忽略/保留的 122 项路径检查通过。Python 字节码缓存已加入忽略规则。

本地证据包含 radare2/rabin2 6.2.4 的格式与导入检查、显式 x86/16 反汇编，以及 Ghidra 常驻候选的只读导出。DRV/OVR 是裸模块，无传统导入表；主 EXE 为 DOS MZ，导入检查同样没有传统导入项。工具的可复现入口为上面的 Python 命令，原始二进制和反编译产物不提交。

本次未修改 GUI、渲染、铜层分类或发布包。字形未恢复的五处铜文字仍然使真实板图的 88 个网络保持“无法确定”。后续可沿已映射的 OVR 入口和常驻绘制调用继续恢复文字路径，仍需原程序单字符样例作为独立行为对照。
