# PCB 文字字段到解释器的静态路径

本页补充 [运行对照步骤](legacy-text-runtime.md) 中的文件方向前提。已从原程序的读取、对象创建、绘制包装及保存路径串起文字字段；这些是静态指令证据，**未完成文件加载、保存往返或字形行为的运行验证**。桌面版本保持 0.9.0，不改变 Qt 读取范围或铜层判定。

## 输入与分析方式

仅适用于已核对的 `PT.EXE`（SHA-256 `abc56e2e8467e608c68a0ddf0b0705e8270c5c60f83f193fa991f10293ece968`）及 `TRAXEDIT.OVR`（SHA-256 `cab0fc0571c5a295c396bd6479a57f060bb18a01d2c2ffc5b438cc1b65f8a0d8`）。复用 [覆盖描述符映射](legacy-overlays.md)，对 OVR 文件偏移 `0x3d639`、`0x41cd4` 的代码块进行独立 `x86:LE:16:Real Mode` 分析；不应用重定位、不拼接可执行镜像、不执行目标代码。

下表的 OVR 地址是“代码块文件起点 + 块内偏移”，不是运行时段地址。常驻地址沿用原 Ghidra 项目的 `0x1000` 基段，换算为原 MZ 段值时减去 `0x1000`。原样 OVR 中的远调用须先结合段值与描述符核对，不能直接沿用独立导入后的自动函数名或反编译参数；字段顺序另外检查了栈传参和字节/字写入指令。

| 位置 | 已核对的作用 |
| --- | --- |
| OVR `0x3d639 + 0x14f9` | 核对 `PCB FILE 4`，按记录分派，包括 `FS` 与 `FT` |
| OVR `0x3d639 + 0x0564` | 读取 `FS` 的六个整数及下一行文字，调用坐标和方向变换，再创建文字对象 |
| OVR `0x3d639 + 0x0901` | 读取 `FT` 的六个整数，检查行尾后读取可选第七整数；缺省值为 0 |
| 常驻 `22fe:38bf` | 按 `DS:d59a` 状态对方向字节查表变换 |
| 常驻 `22fe:06fc` | 分配文字对象并写入坐标、高度、方向、笔宽、层及字符串 |
| 常驻 `2964:53a3 → 2964:39a2` | 将对象字段交给既有笔画解释器，另保留低缩放替代路径 |
| OVR `0x41cd4 + 0x054a` | 保存文字记录；输出同一方向字节、笔宽字节和层字节 |

读取路径支持六字段 `FT`，因此不能仅因研究样例没有第七字段就认定格式错误。上述检查也不能证明 `C00.PCB` 的全部字段、状态及显示路径在运行中均正常，更没有定位此前灰色画面无菜单的原因。

## 字段与对象布局

`FS` 数值行为 `x y 高度 方向 笔宽 层`。对象创建指令对应关系如下：

| 文件内容 | 对象内偏移 | 静态处理 |
| --- | --- | --- |
| x、y | `+0x00`、`+0x02`，各 word | 先经过当前坐标变换 |
| 高度 | `+0x04`，word | 交给解释器后先整数除以 12 |
| 第四整数：方向 | `+0x10`，byte | 读取时取低 8 位，再按当前方向变换状态处理 |
| 第五整数：笔宽 | `+0x0e`，byte | 创建时写低 8 位 |
| 第六整数：层 | `+0x0f`，byte | 创建时写低 8 位，同时参与选择对象列表 |
| 下一行文字 | `+0x11`，短字符串 | 文件读取请求上限 80；对象创建中的复制请求上限为 32 |

绘制包装从 `+0x10` 取方向、从 `+0x0e` 取笔宽并分别传入 `2964:39a2`。保存函数从这三个 byte 字段读值并零扩展为十进制输出；方向位没有在该保存函数中另行编码。读取、创建及保存片段未见方向范围校验，不等于已经确认整个程序接受任意方向值，也不应据此仿照原程序截断非法输入。

对象复制的 32 字符限制与笔画解释器的 80 字节读取能力是不同层次；现有静态笔画工具描述的是解释器能力，不能用其 80 字节上限保证原 PCB 文字对象完整保存或显示 80 字符。长文字仍需独立运行样例核对。

## 方向映射的条件

`22fe:38bf` 读取 `DS:d59a`：低四位决定重复旋转查表次数，随后依次处理 `0x10`、`0x20` 状态位。三个表位于数据段 `DS:0714`、`DS:06ac`、`DS:0644`；每表当前核对的布局为 52 个 word，函数取所选 word 的低字节。

所以应区分三个量：PCB 文件第四整数、当前导入/放置变换状态、送入笔画解释器的对象方向字节。**当 `DS:d59a == 0` 时，本方向函数不改写文件方向的低 8 位；当前运行样例是否满足这一状态仍未观察确认。** 非零状态会改变映射，例如单次旋转状态将方向 0 变为 1，`0x10` 状态将方向 0 变为 16。这里的状态位不能直接当作文字内部镜像位的另一名称。

这条静态链补上了“文件方向如何到达解释器”的条件依据。它仍不能将文件方向 32、48 或组合值标为已运行接受，也不能证明 Qt 当前支持的 `0..3`、`16..19` 就是原程序完整范围。Y 镜像和组合验证应在确认实际加载与变换状态后进行。
