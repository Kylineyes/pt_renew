# 原文字形的受控机器码交叉验证

日期：2026-10-24。基线 `291feba`，研究分支 `research/legacy-text-machine-verification`；产品保持 0.10.0。

已在现有 Unicorn 2.1.4 的 16 位 x86 仿真环境中执行原 EXE 的文字解释器，对 **21,792 个输入组合、105,504 条中心线**逐项比较，未发现与研究工具的差异。另对对象绘制包装的 **512 个用例**及方向变换的 **512 个用例**完成核对。此结果提高了算术、字符前进及函数参数路径的可信度；**没有完成 DOS 程序的独立画面对照，`runtime_verified=false`**。

输入仅使用本地隔离副本；没有提交原程序、字形数据、机器码、截图或仿真内存。没有新增应用依赖或修改 Qt 渲染、文件方向范围、铜层分析与发布包。

## 桌面尝试与停止原因

verification-40 最初创建副本在 `runtime/pt`，配置却仍挂载 `runtime-without-dft`，首次启动日志只记录 COMMAND 和 mount，没有执行 PT。这是本轮准备脚本的路径错误，不能解释为原程序失败。核对 PID 后终止首次目标 18992，再修正隔离挂载并启动 PID 25364，窗口标题实际为 PT。

修正配置使用 PowerShell 的 UTF-8 写入，附带 BOM，第二次启动没有取得新的完整启动日志；现存 `dosbox-startup.log` 属于首次启动，不能用它否定第二次 PT 执行。后续配置应由 Python 明确以 UTF-8 无 BOM 写入，并在启动前断言挂载目录、PT.EXE、PCB 和日志路径。

Orca 的窗口截图显示桌面壁纸，键盘工具报告 `window_not_focused`。当时尝试 AppActivate 和 SendKeys，未核对到目标获得前景，也没有送达原程序的证据。随后运行原生窗口观测，确认前景为 session 3 的 **Windows 默认锁屏界面，LockApp.exe**。在此证据出现后停止桌面输入，没有解锁系统或继续恢复焦点；壁纸不是客体画面，窗口标题也不能证明样例已载入。

已按 PID、进程名和本轮配置命令行核对后清理目标，最终查询没有 DOSBox 残留。`.local-analysis/verification-40/verification-summary.json` 和 `native-stop.json` 保留两次启动、锁屏、日志限制及输入核验结果。原安装 99 项、运行副本 103 项的文件集合和 SHA-256 均未变化。

## 仿真范围与复现

继续使用摘要为 `abc56e2e8467e608c68a0ddf0b0705e8270c5c60f83f193fa991f10293ece968` 的 PT.EXE。按 MZ 头读取装载模块和重定位表，装入独立仿真内存，装载基段为 `0x1000`。执行地址沿用既有 Ghidra 地址体系：

| 路径 | 验证内容 |
| --- | --- |
| `2964:39a2` | 原文字解释器的算术、分支、表访问、抬落笔、字符前进 |
| `3c97:0244`、`3c97:0644` | 原栈检查和短字符串复制辅助函数 |
| `2964:20ef` | 截获绘线调用的六个栈参数，记录中心线及请求线宽，模拟返回；不执行绘图 |
| `2964:53a3` | 原对象绘制包装，核对字段到解释器的栈参数及简化路径分派 |
| `2964:22d3` | 截获简化绘制参数并模拟返回，不验证其轮廓或像素 |
| `22fe:38bf` | 原方向变换函数，对指定全局状态和输入字节执行查表 |

数据段、默认字形表远指针、输入短字符串、初始坐标、线宽开关和变换状态由实验明确设置。没有执行 DOS 启动、PCB 读取、对象分配、保存、OVR 装载或 GRAPH.DRV。因此，本轮不能确认实际启动时使用了这些全局状态、字体指针或同一绘制路径。

执行限制包括：每次调用最多 250000 次指令钩子；仅允许进入上述明确函数范围，意外函数或中断立即失败；非栈数据读取检查声明区域，写入限制为栈及所需状态/对象区域。解释器、辅助函数和方向函数在最终矩阵中使用原生远返回；只有截获的绘图调用模拟返回。

本机在对全部栈读取安装 Unicorn 读取钩子时，原函数远返回曾出现错误跳转；去掉栈读取钩子、保留栈写入及非栈读取检查后，原生返回正常。另以自建合成调用程序核对分段调用和返回桥；这些有限实验不定位 Unicorn 的普遍缺陷，也不作为原程序错误。最终解释器矩阵没有启用辅助函数返回桥，避免把控制流替代悄然混入比较。

本地复现脚本及输出在 `.local-analysis/verification-41/`：

```powershell
python .local-analysis/verification-41/compare_matrix.py .local-analysis/verification-40/runtime/pt/PT.EXE 12
python .local-analysis/verification-41/compare_matrix.py .local-analysis/verification-40/runtime/pt/PT.EXE 1 11 23 24 239 240 251 252 1200
python .local-analysis/verification-41/verify_object_paths.py .local-analysis/verification-40/runtime/pt/PT.EXE
python .local-analysis/verification-41/summarize.py
```

`machine_text.py` 从摘要匹配的 EXE 只读加载原始字节，`compare_matrix.py` 逐项比较截获结果与 `tools/inspect_legacy_text.py` 输出，`verify_object_paths.py` 检查原包装和方向函数。`verification-summary.json` 保存脚本、结果文件和代码范围的摘要及环境版本。研究工具使用已有 Python 3.15.1、Unicorn 2.1.4；Capstone 5.0.7 只用于局部反汇编核对。它们不是桌面应用依赖。

## 解释器比较结果

| 检查项 | 输入与判据 |
| --- | --- |
| 字符索引 | 单独执行低 7 位为 1–127 的 127 个槽位；零索引仍拒绝 |
| 旋转镜像 | 0–3、16–19、32–35、48–51，共 16 种内部方向 |
| 高度 | 1、11、12、23、24、239、240、251、252、1200，共 10 组 |
| 字符间前进 | 空串、AA、A A、前后空格、AV、AUTOTRAX；比较每字符起点和最终位置 |
| 非零原点及线宽 | 部分用例原点 (2000,-2000)、请求线宽 7；与平移后的工具中心线逐条比较 |
| 高位别名 | 额外核对 0xC1、0xFF 对应的低 7 位索引 |
| 长字符串及线宽开关 | 高度 12 下，32/80 字节字符串、16 个方向、请求线宽 11 且线宽开关关闭，核对实际绘线参数被置为 1 |

累计执行 **15,666,440 次解释器/辅助函数/截获边界指令钩子**，比较 21,792 次，中心线 105,504 条；坐标、字符起点、最终位置和线宽参数均无差异。本矩阵中没有触发研究工具的溢出拒绝；不能据此扩展到原程序 16 位回绕、非法方向或表前索引行为。

这些结果支持当前的高度先整数除以 12、旋转后镜像、逐字符落笔复位及字符间沿用位置的实现。捕获的是绘线中心线与参数，未执行绘图函数，不能声称线宽对应的铜面积或屏幕轮廓已经验证。

## 对象包装与方向函数

对象包装矩阵由实验直接构造 F 文字对象：高度 239/240/251/252，视图缩放值 1/59/60/61/62/63/64/100，16 种方向，共 512 次。256 次进入解释器、256 次进入简化路径，均符合原指令条件：**高度除以视图缩放值小于 4，且边界计算状态为零时，选择简化绘制**。

进入解释器时逐项核对颜色、笔宽、方向、高度、Y、X 及 `+0x11` 字符串远指针，并将实际中心线与工具结果比较；进入简化路径时仅核对实际传入的边界参数。没有测试边界计算状态为 1 的执行，也没有证明简化绘制与完整字形视觉等价。

方向函数另做 512 次调用：在 `DS:d59a=0` 时检查所有 256 个输入字节均保持不变；16 种有效变换状态与16种内部方向交叉的 256 次调用，与已核对表的顺序组合一致。这确认了原函数在指定状态下的执行结果，但未观察到真实 PCB 导入期间的 `d59a`，也没有运行完整 FS 读取链。文件方向 32/48 等仍不能据此标记为已由原程序 GUI 接受。
