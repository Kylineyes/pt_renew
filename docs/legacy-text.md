# 原文字形的静态证据与检查工具

本轮在 `research/legacy-text-path` 分支继续覆盖模块研究，桌面应用仍为 0.9.0。已定位默认笔画表和文字解释路径，新增 `tools/inspect_legacy_text.py`，**尚未完成原程序单字符独立行为对照，也未将字形用于 Qt 绘制或铜层分析**。

## 定位依据

复用 [覆盖模块映射](legacy-overlays.md) 的完整 JSON，按常驻绘图目标汇总 OVR 调用候选，再检查相关常驻包装函数及其被调用函数，没有重新依赖文字字符串扫描。

- OVR 文件偏移 `0x49ee`、`0x7e2b`、`0xf8b3` 三块中，共有 17 个指向原段地址 `1964:53a3` 的远调用候选。它们仍只经过 `9A` 模式及段重定位关联，未证明这些 OVR 指令的可达性。
- 已有 Ghidra 项目中的 `2964:53a3` 读取对象坐标、高度、标志、宽度和偏移 `+0x11` 的短字符串，然后调用 `2964:39a2`。
- `2964:39a2` 逐字符解释指令，落笔时调用 `2964:20ef`。这比仅凭邻近地址或表外观认定字形更有依据，但仍属于静态路径证据。
- `2964:780e` 内的 `2964:7b43..7b4c` 初始化远指针 `DS:0xd4f0` 为 `2964:821f`；启动函数 `3c97:0000` 的数据段引用对应 `3ea6`。

这里的地址使用既有 Ghidra 的 `0x1000` 基段；原 MZ 段值应减去 `0x1000`。因此默认表的文件偏移为 `0x3de0 + 0x1964 × 16 + 0x821f = 0x2563f`。只解释默认指针所指的表，未证明运行中该指针永远不变。

## 指令规则与范围

以下规则同时核对了反编译和原指令。解释器输出板坐标中的相对中心线，不生成铜面积。

1. 字符串按最多 80 字节的短字符串读取。每个字符先取低 7 位 `c`，记录起点为 `table + (c - 1) × 25`。低 7 位为零会读到表前内存，工具明确拒绝；高位别名仅描述静态索引行为，不代表已确认代码页。
2. 每个字符开始时落笔，位置沿用上一个字符的终点。指令 `1` 为落笔，`2` 为抬笔；其他小于 12 的值在该路径中跳过。抬笔移动仍改变当前位置。
3. 值大于等于 12 的指令，高四位为距离，低四位选择 X/Y 方向表。高度先执行有符号整数除以 12；正高度的缩放值为 `height // 12`，再分别乘以方向值和距离。高度不是最后统一乘到连续坐标上的浮点比例。
4. 低四位旋转值 0、1、2、3 分别将位移变换为 `(dx, dy)`、`(-dy, dx)`、`(-dx, -dy)`、`(dy, -dx)`。随后 `0x10` 取反 X 位移，`0x20` 取反 Y 位移。
5. 字符间没有在该循环外额外累加固定字距；各记录末端的抬笔移动也参与下一字符起点。基线、可见边界与宽度仍须对照真实输出，不能把最终位置直接视为排版包围盒。

原代码使用 16 位运算。研究工具逐步检查有符号 16 位范围，遇到乘法、取反或位置累加溢出便拒绝，没有用 Python 宽整数伪装原程序溢出结果。只接受低四位为 0..3 且仅包含上述两个镜像位的方向值。

包装函数还包含低缩放替代路径：当高度除以视图缩放小于 4 且不在边界计算状态时，会调用另一简化绘制函数；主解释函数也会依全局状态改变线宽或累计边界。当前工具不模拟这些状态，不输出线宽面积，不处理 VGA 像素、裁剪、DRC 或生产判断。

## 使用

仅用 Python 标准库，默认输出摘要，不输出原始表或笔画：

```powershell
python tools/inspect_legacy_text.py 'D:/软件/PT.EXE'
```

指定文字后输出静态推导的中心线和每字符起终点，供本地研究对照：

```powershell
python tools/inspect_legacy_text.py 'D:/软件/PT.EXE' --text 'A A' --height 251 --orientation 0x11
python -m unittest discover -s tests -p test_legacy_text.py
```

JSON 标记 `evidence: "static_instruction_derivation"` 和 `runtime_verified: false`。成功退出码 0 仅表示通过摘要/结构检查及请求范围检查；不代表原程序运行对照成功。失败输出中文 JSON `error` 和退出码 1；单文件最多读取 16 MiB。错误版本、零索引、超过 80 字节、不能编码为 Latin-1 的文字、非法方向位和 16 位溢出均拒绝。

## 文件对象路径补充

后续研究已从 `FS` 读取、当前变换、对象创建及保存路径核对方向与笔宽字段，见 [PCB 文字字段的静态路径](legacy-pcb-text-path.md)。文件方向与内部方向的对应受当前变换状态影响，运行映射仍未验证；对象创建中的字符串复制请求上限为 32，与本工具描述的解释器 80 字节上限不同。

## 验证与待办

14 项独立合成测试覆盖抬落笔、字符间位置延续、逐字符落笔复位、空白移动、整数缩放、四向旋转及旋转后的镜像、高位别名与零索引、短字符串上限、槽位和零填充、溢出拒绝、摘要门槛、CLI 成功/错误以及输入不变。测试使用自行构造的非对称方向与指令，没有包含原软件字体数据。CMake 找到 Python3 时将它们作为 `pt-legacy-text-tests` 加入 CTest。

本地真实 EXE 已通过摘要和表结构核对，`A A`、高度 251、方向 `0x11` 的静态结果为整数缩放 20、12 条中心线、终点 `(0, 720)`。这是工具推导输出，不能作为原程序行为对照。

已建立原程序隔离副本及包含单字符、相邻字符、空白、非 12 倍数高度、旋转和镜像的九组样例，并启动 DOSBox-X。桌面工具反复返回 `USER_CONTROL`，没有取得应用画面或完成交互，因此**未确认样例被原程序载入，也未完成单字符对照**。后续需在桌面可用时继续该对照，再决定是否实现任何字形功能。
