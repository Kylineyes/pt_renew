# NET / NETDEF 只读兼容与引脚映射

阶段：第六阶段，版本 0.6.0。开发分支：`feat/legacy-netlist-compatibility`。

## 1. 验收结论与能力边界

已实现外部 Protel 文本网表读取、受限的 PCB 内嵌 NETDEF 读取、节点到焊盘的只读映射、来源切换、网络筛选、高亮与节点定位。

**这里只检查声明的“元件-引脚”能否映射到板图对象，不检查铜线实际连通、断路、短路、间距或 DRC，也不生成布线。** 高亮为焊盘轮廓，不绘制可能误导为真实走线的连线。完整生产兼容尚未建立。

使用现有参考文件只读验证的结果：

| 输入 | 结果 |
| --- | --- |
| DEMO.NET | 36 个元件声明，88 个网络，370 个显式节点 |
| 对应 PLACED.PCB | 370 个节点唯一映射，缺失 0，歧义 0，跨网络冲突 0，同网重复 0 |
| GND | 53 个节点；实际筛选后对应焊盘高亮 |
| J2/J3 | 网表封装 DB9RA/F、板上封装 DB9；报告差异，不自动替换 |
| 注释字段 | 报告 J1、J2 等注释差异，不改写板上实例 |

这些结论由实际文件结构、C++ 诊断程序、测试及真实窗口共同验证。无需用户额外挑选网络才能运行已有参考样例；测试真实业务板和制造规则时才需相应输入和验收标准。

## 2. 外部 NET 布局

本地 DEMO.NET 无头部标记，采用按行分隔的两种顶层块：

```text
[
元件标号
封装名
注释
后续附加字段（可为空）
]
(
网络名称
元件-引脚
元件-引脚
)
```

- 本地 36 个元件块中，标号、封装、注释后都还有三个空字段。读取器保留原附加行，不擅自赋予属性语义；非空附加字段在检查结果中提示。
- 空白、CRLF/LF 和一个尾部 DOS EOF（0x1A）得到支持；EOF 之后只能是空白。中途 EOF、重复 EOF 或之后仍有网络/板图内容会拒绝，不截断后伪装读取成功。
- 保存原始输入快照与 SHA-256，大小/摘要包括原 EOF、换行及空白；用于解析的文本边界不改变输入身份。
- 标签与节点当前只接受已确认的 ASCII；非 ASCII 或未知代码页会明确拒绝，不能将含替代符的名称当作精确电气标识。
- 顶层未知记录、块嵌套、缺失终止符、错误节点和控制字符均停止读取。不会返回半份成功网表。

资源保护：NET 文件最多 8 MiB，单行最多 64 KiB，最多 300000 行、20000 个元件声明、20000 个网络及 200000 个节点。元件块附加字段最多 64 行，标识最长 255 字节。这些是本工具限制，不是对原软件规格的推断。

## 3. 内嵌 NETDEF 布局与证据强度

本地 PLACED.PCB、660A.PCB、TRAXEDIT.ABK 未发现 NETDEF，**因此此部分只有公开格式结构描述与合成样例验证，没有本地原始 NETDEF 的运行对照**。

当前支持的受限结构为：

```text
NETDEF
网络名称
[ 可选的独立元数据块 ]
(
元件-引脚
{ 可选的独立节点元数据块 }
元件-引脚
)
```

上例方括号和花括号必须在独立行；不表示支持单行写法。允许列表前/内出现已界定的非嵌套元数据块，显式节点仅从列表内容读取。元数据保留原始字节（包括 CRLF 与空白），不按未知字段推导电气属性。

- NETDEF 只能位于 PCB 顶层，不能在 COMP 内；解析后继续读取后续几何记录，不吞掉后面的 FT 等图元。
- 多个 NETDEF 分别保留，重名网络不自动合并。
- 未闭合或嵌套的元数据、未知结构及截断会使整块板图读取失败，不悄悄遗漏网络。
- 单节和累计 NETDEF 文本最多 8 MiB，累计节点 200000、网络 20000；板图仍受既有 64 MiB 上限限制。
- PCB 原始快照和网表中的来源摘要指向整块板图，不伪造独立 NET 文件摘要。NETDEF 网络的源行指向名称行；节点源行使用完整 PCB 行号，而不是片段内行号。

结构交叉参考：<https://github.com/KiCad/kicad-source-mirror/blob/master/pcbnew/pcb_io/autotrax/autotrax_parser.cpp>。仅交叉核对公开格式事实，未复制其 GPL 解析器实现。后续仍需真实原程序产生的样例来扩展和确认格式变体。

## 4. 映射与歧义处理

- 从板图 COMP 标号和其所属 CP 名称组合出完整键 `标号-引脚名`，与网表节点**区分大小写精确匹配**。
- 不按首个或最后一个连字符拆分，因此元件名/引脚名自身带连字符、负号引脚也可正确比对；组合键碰撞则报告歧义，不猜测分隔位置。
- 自由焊盘没有元件归属，不会被凭空归入某个声明元件。
- 报告缺失节点、重复元件标号/声明、重复网络名、同网重复节点和同一引脚的跨网络归属冲突。
- 重复网络名不自动合并，其节点按歧义处理，禁止自动高亮或定位。冲突或多候选节点也不参与可用焊盘列表。
- 歧义候选至多保留两个示例索引来证明“多于一个”，状态显示数量下界；原板图和网表完整保留，不做数据截断或自动去重。
- 映射计数按节点出现次数统计。同一节点可同时具有几何唯一匹配与跨网冲突，因此 `resolved` 不是“正确布线数”，冲突应单独检查。高亮列表按有效焊盘去重。
- 同名元件的封装或注释不同只报告差异，不替换封装、不变更板图实例。

没有网表时显示空状态；没有板图时可以只查看外部声明，明确提示未进行焊盘映射。节点数为零或少于两点只作提示，不据此断言网络已导通。

## 5. GUI 与键盘入口

- “网络 → 只读载入外部 NET”（画布旧式 **N→G**），现代快捷键 **Ctrl+Shift+N**。
- “网络 → 网络与引脚映射”（画布 **N→N**），现代快捷键 **Ctrl+Alt+N** 聚焦筛选框。
- 网络名称筛选是**不区分大小写的字面子串筛选**；这只是搜索体验，不改变数据匹配的大小写规则。
- 选中网络后高亮无歧义、无冲突的匹配焊盘。激活节点（例如选中后按 Enter）将视图中心定位到该焊盘并显示只读属性。
- 隐藏图层不会自动打开，隐藏对象不额外绘制选择轮廓；不因定位而泄露该层的视觉高亮。
- “高亮 → 清除网络焊盘高亮”取消当前网络高亮；普通图元选择是独立状态。
- 内嵌 NETDEF 和外部 NET 通过来源下拉框明确切换，**不自动合并**。移除外部网表后回到板内来源；没有内嵌来源时显示空状态。
- 载入其他板图或关闭板图会清除外部网表和高亮，避免继续使用上一块板图的节点映射；库浏览器依然独立。
- 外部文件读取在后台执行，板图更换或显式放弃后丢弃迟到结果。映射与列表更新目前在 UI 线程执行，尚未做上限规模的响应性基准，不承诺大型数据全部无延迟。

修正了定位后 Dock 布局改变引起的视口中心漂移：画布尺寸改变时同步缩放平移量，保持中心板坐标。测试同时覆盖隐藏图层定位的像素不变。

## 6. 运行与诊断

可同时指定 PCB 与 NET；命令行会等待板图成功读取后载入外部网表，避免后台任务的时序冲突：

```powershell
& .\dist\pt-renew.exe 'D:\project\pt_renew\pt\PLACED.PCB' --netlist 'D:\project\pt_renew\pt\DEMO.NET'
```

也可以仅用 `--netlist` 查看声明；以后载入板图会重置外部来源，需要重新载入 NET。

诊断工具只需 Qt Core，不启动 GUI：

```powershell
& .\scripts\Enter-QtEnv.ps1
& .\build\release\pt-netlist-check.exe 'D:\project\pt_renew\pt\DEMO.NET' 'D:\project\pt_renew\pt\PLACED.PCB'
```

第二个参数 PCB 可省略。JSON 输出包含网络/节点数、映射/缺失/歧义/冲突/重复计数、来源摘要和差异说明。退出码 1 表示读取/结构失败，2 表示缺失/歧义/跨网冲突，0 表示未触发这些错误。**0 不代表 DRC 通过**；仅解析 NET 而未传 PCB 时也可能返回 0，必须同时检查 `board_loaded`。封装/注释差异和同网重复作为诊断信息，不能只看退出码忽略它们。

六组测试在 Debug 和 Release 均通过，各配置为：菜单 18、PCB 29、选择 18、导航 9、LIB 25、网表 30，**合计 129 项通过、0 失败、0 跳过**（包括各组初始化/清理）。新增测试覆盖严格格式、DOS EOF、元数据字节保留、完整文件行号、重复/冲突/缺失/歧义、内外来源切换、迟到结果、诊断退出码、菜单与快捷键、只读输入及关闭清理。

最终 Release 部署包在移除 Qt SDK PATH 的环境中实际启动：

1. 载入原始 PLACED.PCB 与 DEMO.NET，界面显示 88 网络、370 唯一映射、零缺失/歧义/冲突。
2. 实际输入 GND，显示 53 节点并高亮对应焊盘，不画伪连通线。
3. 激活 C1-1，定位并选择 C1 焊盘：中心 (1925,2175) mil，尺寸 62×70 mil、孔径 30 mil，源 PCB 第 278 行。
4. 移除外部网表后，网络列表、来源和网络高亮清空，主板图与独立选择保持不变。
5. 所有截图已实际读取检查；原始安装目录 99 个文件 SHA-256 全部未变。测试源码使用合成小样例，原文件、截图、构建和本地诊断不提交。
