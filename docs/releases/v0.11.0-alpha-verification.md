## 受限交互与过程偏差

所有消息均只向本任务创建的发布进程窗口发送，输入前核对原 PID、原创建时间、完整 image 路径以及精确窗口身份；关于窗另核对 owner。仅使用定向 Win32 消息和 `PrintWindow`，没有全局键鼠、全屏截图、旧控制服务、旧 Task 查询、产品重启或强杀。截图只包含该自建窗口。

首次主窗图 `main-window.bmp` 受 Windows DPI 虚拟化影响裁切，仍保留。父批准后，使用 DPI 感知的同类 `PrintWindow` 对同一主窗补观察，得到完整 `2182×1331` 的 `main-window-full.bmp`；原 Pi 已分别实际读取初图和补图。

首次对主窗发送 `I` 按下／松开各一次后，信息菜单成功出现，但本地核验脚本把 Qt 弹出菜单标题预设为空，实际标题为 `pt-renew`，因此保护性断言停止，未发送 `A`。原控制器一直保留原产品 Popen 和原句柄；失败状态保存在 `gui-state-blocked-original.json`，没有修改正在运行的控制器。

父审阅后先批准只观察该已出现菜单；到补观察时，菜单已因失焦消失，精确窗口校验再次停止，没有新输入。随后父通过问题 `msg_8b85e4c37399` 明确批准一次新的、同进程只读菜单动作 `reopen-information-about-20261031-once`，允许在同一工具内重开信息菜单并立即选择关于，不允许继续追加重开或新进程。

该明确动作对原主窗发送一次 `I` 按下／松开，核对新菜单 HWND `19336074`、精确 Qt 弹出类与标题，保存菜单截图后发送一次 `A` 按下。`A` 已触发关于，菜单随即消失，脚本在松开前的精确菜单校验停止，故未继续向消失菜单发消息。没有重发 `A` 或换输入入口；随后仅补观察确认关于窗身份并成功截图，原 Pi 直接看图确认通过。此补充操作及全部原始输入和观察记录均保留，没有把脚本断言失败改写成从未发生。

正常关闭由父明确批准的受限补充脚本执行，原控制器处于保留对象的异常等待分支；因此其最终 `gui-state.json` 仍保留 `phase=blocked` 与首次脚本异常，同时新增 `exit_code=0` 和实际结束时间。这表示原验收脚本存在保护性失败，不能据此解释为产品退出失败。整体结论由原退出证据、独立补充记录及前后摘要审计共同支持。
