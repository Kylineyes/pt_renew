# 见证器venv重定向缺口与基础Python直启修正

[资源复用现场](control-bitmap-surface-live.md)完成了单组GUI、7个正常资源寿命和8509次上传取证，但整体Task按failed结算。原因是venv启动器PID28300的原Popen exit0不能代替实际监督器PID66568的独立精确退出证据；该实际监督器没有在退出前被单独持柄。其当前已不存在，只能说明当前没有该活进程，不能事后补作历史exit0。父早期审计已保留并由[更正审计](../.local-analysis/control-bitmap-surface/parent-independent-live-audit-corrected.json)明确收窄结论。

本次后续开发在`fix/control-witness-launch`独立分支进行，新增[见证器直启工具](../tools/control_witness_launch.py)和[4项无GUI测试](../tests/test_control_witness_launch.py)。它只解决证据侧启动身份核验，不修改产品、控制包、资源适配器、已运行客户端或失败状态；不把新测试当作补做现场。

`base_python`首先通过标准库探针解析所选环境的`sys._base_executable`，再验证该基础解释器的探针实际PID与其原Popen PID一致。`WitnessLaunch`使用这个基础解释器，带`-I -S`运行工具自己的握手入口；入口先写实际PID、解释器路径、目标脚本摘要及10秒放行截止，暂不运行目标脚本。

父侧核对原Popen PID、子进程实际PID、解释器路径和摘要后，才允许显式`release()`。子进程再次核对放行PID、摘要和期限，然后用同一进程的runpy执行标准库证据脚本。因此目标监督器本身就是原Popen持有的进程，不再只持venv重定向外壳。正常或失败退出均由`wait()`记录真实退出码，非0不会重启或改写为成功。

| 边界 | 行为 |
| --- | --- |
| 未完成身份握手 | 不运行目标脚本，异常携带pending_launch保留原Popen所有权 |
| 目标脚本在握手后变化 | 拒绝放行，子进程自行在未放行截止后退出，不kill |
| 错误放行身份或摘要 | 子进程拒绝执行目标脚本 |
| 重复放行、进程已退出或放行超时 | 拒绝再次执行 |
| 目标脚本返回非0 | 保留原退出码，只有这一次进程，不自动重启 |

10秒是**服务启动前的身份放行期限**，不能替代或延长现场客户端600/900秒预算。上层调用方在异常后必须保留pending_launch并正常等待退出；工具不杀进程。该工具不生成桌面许可、Task/Dispatch，也不持其他进程的桌面权限。

适用对象仅为使用标准库的证据侧监督器/外层见证器，不能直接把带`-S`的基础Python用于控制客户端。下一版监督器必须显式使用冻结MCP venv的解释器启动控制客户端，再精确见证其完整子孙链；监督器自身则由本工具原Popen直持。禁止依赖监督器中的`sys.executable`自动推断客户端解释器。

4项新增测试实际运行标准库命令行子进程，核对基础解释器、放行前无目标副作用、同PID执行与exit0、非0退出不重试、脚本变化拒绝及原Popen保留。**相关仓库测试共110项通过**，输出[本机测试记录](../.local-analysis/control-bitmap-surface/tests-with-witness-fix.log)。这些子进程没有MCP、Win32窗口、截图、输入或钩子；冻结现场客户端此前6项检查保持独立，不重复计入。

本轮没有用新工具重跑桌面或改写`candidate-final`。下一轮如需现场，须先把新监督器显式客户端解释器、直启工具和退出策略纳入新冻结摘要及新任务方案；新批准后再运行，旧任务`task_142ea7a86a8d`/`ctx_af9c3c5211fd`已经failed结算，不能续投旧inbox或以新工具补造旧退出证据。GUI/资源/本组健康记录仍是有效分项结果，控制长期稳定性和产品竞争均未因此通过。
