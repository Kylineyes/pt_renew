# 命令、视图与测量

[文档导航](../README.md) · [操作指南](../usage.md) · [完整资料索引](../reference-index.md)

## 先看结论

鼠标菜单、现代快捷键和画布内旧式字母入口共用命令模型。查看、选择、定位、两点测量及可选端点捕捉已有实现；文字输入保持局部焦点语义，未实现业务继续显示禁用状态。

## 第一层分析：从操作意图到命令

原软件有 17 个一级菜单，TRAXEDIT.MNU / KEY 体现菜单及按键序列。重建时保留用户的操作路径，再将同一业务绑定到统一命令与 QAction。例如文件加载的鼠标入口、Ctrl+O 和画布 F→L 调用相同功能。

一个命令是否可用由当前文档、选择、活动工具及能力门决定。旧式字母只在画布焦点中解释；文本框里的 F/P/T、撤销或取消仍应服从文本及窗口上下文。F3 与 P→T 对应的正式新增仍禁用，见[编辑主题](editing.md)。

## 第二层分析：视口、选择和测量分开

| 行为 | 改变的状态 | 保持的边界 |
| --- | --- | --- |
| 缩放、平移、图层显隐 | 视口和可见对象 | 不改文件几何 |
| 选择、重叠切换、属性 | 当前文档内的图元引用 | 来源随文档有效，隐藏／换图后失效 |
| 元件检索、节点定位 | 视图中心与选择 | 不移动元件、不自动打开隐藏层 |
| 两点测量 | 点、距离、角度及来源 | 自由屏幕取点可有像素误差 |
| 几何端点捕捉 | 本次取点使用的模型坐标 | 不捕捉文字、网格或推测交点 |

选择容差为 6 个 Qt 逻辑像素；测量捕捉半径为 10 个 Qt 逻辑像素，再换算成板坐标。捕捉开关开启不保证每个点都已捕捉，面板分别记录两端真实来源。

| 代码入口 | 职责 |
| --- | --- |
| [CommandCatalog.h](../../src/application/CommandCatalog.h) | 命令目录与共享能力门 |
| [MainWindow.h](../../src/ui/MainWindow.h) | 命令可用状态与派发 |
| [BoardCanvas.h](../../src/ui/BoardCanvas.h) | 视口、焦点、选择和取点 |
| [EndpointSnapIndex.h](../../src/geometry/EndpointSnapIndex.h) | 模型候选查询，不创建图元控件 |
| [Measurement.h](../../src/domain/Measurement.h) | 两点坐标与来源 |

## 第三层分析：怎样判断操作正确

既有真实 GUI 已核对菜单、选择、测量和捕捉；合成 300/400/500 几何得到 500.00 mil，隐藏目标层后回到自由取点。键盘焦点、菜单状态和失效清理由 Qt 事件测试覆盖。各阶段的 GUI 和自动测试分别计数，不能把某次工具文字回执当作操作后验。

文字按近似边界选择，八角／圆角焊盘仍有近似轮廓。现有小样例和候选查询测试未证明最大板图的帧率、延迟或制造测量精度。

## 下一步怎样推进

随新工具补充焦点、取消、换图和隐藏层规则，再验证不同入口是否到达同一命令。大型板图先测量实际性能，再决定索引优化；活动编辑工具的网格和约束须单独设计。
