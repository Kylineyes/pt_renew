## 图元计数的来源

Status 在 `I+0cae` 先调用块内 `I+09ef` 重新统计，随后把以下 32 位累计值转换成字符串，存入步长 `0x51` 的显示缓冲区。这里的标签语义来自同一样本 MNU，数量来自当前内存模型的遍历；不等于直接统计 PCB 文件中的记录行。

| Status 行与标签 | 低字地址／高字地址 | 显示缓冲区 | 统计实现与来源 |
| --- | --- | --- | --- |
| 3 Arcs | `DS:0d8a`／`0d8c` | `DS:caa2` | `I+072c` 遍历，通过节点 `+0x0a` 继续 |
| 4 Components | `DS:0d8e`／`0d90` | `DS:caf3` | `I+0957` 遍历 `DS:9a44` 组件链，节点 `+0x68` 指向下一项，每项累计 1 |
| 5 Fills | `DS:0d92`／`0d94` | `DS:cb44` | `I+06cd` 遍历，节点 `+0x0a` 继续 |
| 6 Holes | `DS:0d96`／`0d98` | `DS:cb95` | `I+088f` 每个 Via 同时累计；`I+0812` 仅在节点字节 `+0x0a` 等于 13 且字 `+0x08` 大于 0 时另外累计 |
| 7 Pads | `DS:0d9a`／`0d9c` | `DS:cbe6` | `I+0812` 遍历，节点 `+0x16` 继续 |
| 8 Strings | `DS:0d9e`／`0da0` | `DS:cc37` | `I+08f8` 遍历，节点 `+0x32` 继续 |
| 9 Tracks | `DS:0da2`／`0da4` | `DS:cc88` | `I+078b` 仅在两对坐标不完全相同时累计，节点 `+0x0c` 继续 |
| 10 Vias | `DS:0da6`／`0da8` | `DS:ccd9` | `I+088f` 遍历，节点 `+0x08` 继续 |

`I+09ef` 先清零这八个双字计数。它遍历索引 0 至 100 的 `DS:984a + 索引×5` Via 表；在每个索引下，遍历 1 至 6 的三组 Track 表，基址分别使用 `DS:9a49`、`DS:a61f`、`DS:b1f5`，地址另加 `索引×0x1e + 子索引×5`。之后对索引 1 至 16 遍历 `DS:be6b` 的 Fill、`DS:be1b` 的 Track、`DS:bebb` 的 String 和 `DS:bdcb` 的 Arc 表；再处理 `DS:9a48` 的 Pad 表和组件链。

组件的子链也参与统计：`I+0957` 将当前节点的 `+0x44`、`+0x49`、`+0x3f`、`+0x3a`、`+0x53`、`+0x4e` 交给 Arc、Fill、Track、String、Pad、Via 对应计数函数。因此不能假设屏幕数值只计入脱离组件的图元。底层取得节点的常驻辅助函数在本轮未完整恢复，字段标签也未与 PCB 格式逐项独立验证；此处只记录能从遍历和累计路径确定的来源。

前两行自由内存值来自常驻调用的返回值，其余三行路径/磁盘值来自其他辅助函数；本轮未将这些裸模块外部函数名解释成具体系统 API。证据均在 `S/overlay-information.json` 的 `0000:06cd` 至 `0000:0c99` 等定向函数。

## Status 的输出门与只读退出

Status 的显示与输出不是同一个无条件动作，控制流如下：

1. `I+0e89` 的专用选择器返回所选行号，结果存入 Status 自己的 `BP-2`。`I+0e91` 调用常驻收尾路径后，`I+0e96` 检查这个实际存储值。若为 0，直接到 `I+1173` 返回，未调用输出文件名询问。
2. 若选择结果非零，`I+0ea5` 调用块内 `I+0014`，传入 `SS:(Status BP-5)` 作为取消码输出指针。辅助函数在 `I+0044` 调用实际常驻 `324e:29c1`，传入菜单 91，其标题为 `SAVE FILE NAME`。这是额外的文件名询问。
3. 辅助函数先复制 `DS:c5cc` 为临时默认文件名。空字符串会把调用者取消码设为 Esc；询问返回 Esc 也直接返回；非空且未取消时，还处理扩展名与已存在文件确认。返回后 `I+0ea8` 检查 Status 的 `BP-5` 是否等于 `0x1b`，相等则到 `I+1173` 返回。
4. 只有“选择结果非零”且“文件名辅助函数返回非 Esc”同时成立，才到 `I+0ebb` 给 `DS:0c8a` 文件记录赋名，再在 `I+0ec5` 打开输出，随后写入各状态行并在 `I+116e` 关闭。两次实际目标分别为原始 `2c97:174f`、`2c97:17c4`；段字 `I+0ebe`／`I+0ec8`，重定位记录 OVR `0x482e`／`0x4830`。

`324e:1a6b` 使用 `DS:04b2` 的结束字符集合，原文件数据对应 Enter 和 Esc 两项；`324e:1d13` 对 Esc 明确将返回行号置 0。因此，**在已经确认 Status 状态页获得焦点后，单独按一次 Esc 并观察返回，是本轮静态支持的只读退出方式**。Enter 会保留非零行号并进入输出文件名询问。若已经看见 `SAVE FILE NAME`，在该询问按 Esc 是第二道取消；不能连续确认。

这里的条件来自实际分支和局部变量写入，没有采用反编译中的 `unaff_CS`、`extraout_AH` 或伪参数。主界面与选择器所做的通用收尾不构成全程序“绝无后台写入”的证明；本页确认的是 Status 专属报告输出被上述门控制。

## KEY 启用、初始化与 Alt+F10

KEY 装载路径得到支持：`1000:02cd`，EXE `0x40ad`，远调用原始 `0250:002a`，段重定位字在 EXE `0x40b0`。KEY 描述符在 EXE `0x62e0`，槽位 2 在 EXE `0x630a`，目标 `K+24e5`，即 OVR `0x1d090`。`K+2512`／`K+251d` 的赋名和读取打开目标分别为原始 `2c97:174f`／`2c97:17bf`，段重定位记录在 OVR `0x1df99`／`0x1df9b`。文件查找成功才会调用装载入口。

| 状态／路径 | 静态可证行为 | 证据地址与文件偏移 |
| --- | --- | --- |
| 宏允许开关 `DS:68b9` | 初始化显式写入 1；匹配触发键后必须非零，才调用宏展开 | `324e:332c`，EXE `0x295ec`；`324e:0b71`／`0b76`，EXE `0x26e31`／`0x26e36` |
| 宏录制开关 `DS:68ba` | 初始化为 0；为非零时进入录制分支，不能等同于普通宏匹配 | `324e:3327`，EXE `0x295e7`；`324e:0ade` 起的分支 |
| 宏计数 `DS:6932` | 初始化清零；KEY 装载器另外在 `K+2581` 清零并在接受定义后递增 | `324e:3333`，EXE `0x295f3`；`K+2793` 起 |
| 临时关闭宏 | 常驻文字输入路径在进入时写 0、结束时写 1；KEY 管理入口及部分键盘询问也存在成对写入 | `324e:1f2e`／`2413`，EXE `0x281ee`／`0x286d3`；`K+22fb`／`230a`、`K+30f6`／`3199` |
| 其他跳过条件 | `DS:4b0f` 非零时直接跳过录制与宏匹配；展开前还检查递归深度和另一个停止辅助函数 | `324e:0ad4` 起；`324e:0965`。本轮不赋予 `DS:4b0f` 未验证的产品语义 |

初始化调用顺序可从入口追踪：`1000:05e3`（EXE `0x43c3`）远调用原始 `224e:5db3`，其 `324e:5dd7`（EXE `0x2c097`）调用 `324e:329b` 初始化输入及宏状态；之后主流程才在 `1000:060e` 调用文件装载函数 `1000:00aa`。所以这里不只是文件初始值推测，而是可达启动路径上的显式设置。它仍不证明任意时刻该开关保持 1。

Alt+F10 的文本常量在 `K+10e4`，OVR `0x1bc8f`；`K+1878` 准备该常量，`K+1884`（OVR `0x1c42f`）把匹配结果设为 `0xf1`。同一个解析函数被 KEY 装载器 `K+269d` 用于触发键、`K+2731` 用于宏内按键。不要把相邻 `<ALT-F2>` 的 `0xe9` 当作 Alt+F10。

底层 `324e:0650` 在字符低字节为零时，将扫描码加 `0x80`，随后执行特殊转换；这些转换不包含 `0xf1`。因此，**如果底层返回扩展键扫描码 `0x71`、字符为 0，队列码就是 `0xf1`，与 KEY 文本解析一致**。`0x71` 与实际 Alt+F10 的对应还受 BIOS/模拟器和宿主拦截影响，本轮未进行运行验证。

固定 KEY 中 `LIST_COMPS` 的定义是 Alt+F10 后展开 Esc、Esc、I、C；它指向 Components，不能用它直接请求 Status。装载数量和内容、当前询问是否临时禁用宏、焦点及宿主是否收到组合键，仍需运行证据。

## Esc 在主循环中的行为

主循环在 `1000:062f` 调用编辑器输入入口 `2964:36cc`，返回字符转换后只在以下路径继续：通过字母集合的字符进入首字母分派，Enter 进入菜单选择，其余直接回到 `1000:0611`。引用的 `DS:04f8` 位集合位于 EXE `0x32d38`，成员恰为 A 至 Z，没有 Esc；`1000:0666`（EXE `0x4446`）明确回跳。数据段来源由运行库 `3c97:0000` 的初始化段值及该立即数字的 MZ 重定位交叉核对，未把代码段内同数值偏移误当作集合。

因此在已经回到此主循环、正常取得 Esc 的条件下，Esc 会落入下一轮等待，**这条主循环中不存在 Esc 退出程序的分支**。这与菜单选择器 Esc 返回零、文字输入 Esc 取消的行为需要按当前上下文区分。此结论不外推到尚未返回主循环的其他命令，也没有解释 verification-28 第二次 Esc 后的 Windows 前景变化。

## 对既有文档与工具的逐项结论

| 项目 | 结论 | 建议 |
| --- | --- | --- |
| Information 为 88、Status 为 89，主菜单序号 8 进入 Information 覆盖块 | 支持 | 保留固定样本范围和运行未验证标记 |
| Status 工作文件名“被复制”到显示行 | 修正 | 改为先调用 `324e:0000`，去目录后拼接名称与扩展名，再写入第 11 行；状态页无法独立证明完整路径 |
| Status 有后续输出分支 | 支持并细化 | 标明专用选择器非零和文件名询问非 Esc 两道条件；优先观察后按一次 Esc |
| KEY 宏开关未知、可能未启用 | 部分补足 | 初始化默认为 1 已证明；当前时刻状态、成功装载和宿主键码仍未知 |
