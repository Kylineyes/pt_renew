## 工作名恢复与命令行的优先关系

此处的静态优先关系与实际DFT是否读入分开，完整默认值及畸形输入边界继续由[EX-005](exploration-backlog.md#ex-005)承接。

内部初始化 `2964:7bbe..7bcc` 将 `DS:c8fc` 置为 `*.PCB`。读 DFT 第 137 行后，`17d1:38f8..3927` 的恢复必须同时满足：

1. `DS:c8fc` 与字面量 `*.PCB` 完全相同（`3902` 比较；不同时跳 `392c`）。
2. 第 137 行字符串经 `324e:4393` 搜索成功（`390f` 调用，`3916` 的 AL 为零时同样跳过）。

两者都满足才将搜索后的名字复制到 `c8fc`。此段**只恢复工作名，没有在此调用板图读取入口**。`POWER3.PCB` 的文本存在并不证明该板内容会自动载入。第 138 行驱动描述不匹配也不会回滚这个已经恢复的名字，只恢复上表明确的显示相关备份。

主流程 `1000:031f` 在 DFT、库／KEY／PAD 等处理后调 `3c97:1fb1` 获取 DOS 参数数。运行库从 PSP 的 `0x80/0x81` 命令尾扫描参数；有参数才在 `1000:0331..0335` 以索引 **1** 调 `3c97:1f62`。本次核定的消费分支如下：

| 条件／步骤 | 固定代码行为 | 证据边界 |
| --- | --- | --- |
| 参数数大于 0 | 复制首参数，上限 80；`0348..0382` 找第一个 `.` 并取其前半，随后 `0387..03aa` 追加 `.PCB` | 只说明该 DOS 解析／字符串分支；不外推现代 Windows 引号、空格、多个参数或点号目录语法 |
| 整理后名字检查成功 | `03b4` 调 `324e:43ed`，AL 非零后初始化板状态，以 **参数 0** 在 `03e3` 调 `17d1:0025`（OVR 槽 1→`14f9`）读板；`03e8..03f6` 把本地名字写 `c8fc` | 这条路径没有再回到 DFT 恢复选择；因此首参数在此分支优先于 DFT 记忆工作名 |
| 首参数名字检查失败 | `03bb` 跳 `0405`，不走本分支板图读取或工作名赋值，接到主循环准备 | 没有自动改读 DFT 第 137 行板图的分支；也不能据此断言任意失败都会清空旧名字 |
| 无参数 | `0326..0328` 跳 `0407`，依序提交内部 `F`、`L` 键请求 | `17d1:2315` 的 File Load 流程以 `c8fc` 作为对话初值；这解释恢复工作名可影响后续加载提示，不等于无参数自动读入旧板 |

命令行分支在调用读板后写工作名，局部没有单独检查一个“完整 PCB 解析成功”的返回值；读板内部错误、异常或部分解析仍须另核。因此“命令行覆盖”在本文指**上述检查通过、调用继续返回到后续赋值的静态控制流**，不把名字检查或某条文件访问日志当成对象解析全部成功。[第八 Status 的文件名与计数](legacy-dosbox-configuration.md#eighth-status-conclusion)才是固定 `SYN1.PCB` 场景的独立实际状态证据。

## 缺失、错误格式及适用范围

缺 DFT 时通用搜索仍会产生尝试；搜索失败后 DFT 函数提前返回，主流程继续其余初始化和命令行处理。这支持“无 DFT 也能继续处理命令行”，而不支持“日志出现 DFT 就读成功”。头部版本不匹配也会提前返回。两种情况都不进入 DFT 参数赋值段。

头部匹配之后，读取是逐项直接写全局，只在尾部扩展前有明确 EOF 分支。本文没有证明截断、非数字、超长或中途 I/O 失败时会完整回滚，也没有把格式错误统一解释成“采用安全默认”。原 DFT 的第 64／65 行同址、驱动不匹配仅局部恢复及尾部兼容逻辑均保持原样。

剩余边界：完整数值字段命名及全部消费者、所有畸形 DFT 变体、缺文件时每次 DOS 返回码、任意命令尾语法和实际新现场中的 DFT 优先对照均未验证。这些限制由本项 [EX-005](exploration-backlog.md#ex-005) 承接；本文完成分配的固定版本启动／历史文件名／命令行静态子题，不结算原长期 Task，不扩大为 FT 默认、保存兼容或历史只读打开原因。
