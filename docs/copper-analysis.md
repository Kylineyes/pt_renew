# 铜层几何连通分析（受限预览）

阶段：第七阶段，版本 0.7.0。开发分支：`feat/copper-connectivity-analysis`。

> 第八阶段（0.8.0）已扩展铜层圆弧建模，见 [铜层圆弧分析](copper-arcs.md)。本文的原始验收计数保留为第七阶段记录；下述几何覆盖说明已补充圆弧支持边界。第九阶段新增具体未覆盖图元的来源诊断和定位，见 [覆盖诊断与文字研究](copper-coverage.md)。

## 结论

已增加可选的**只读、受限几何分析**。它基于当前解析到的走线、焊盘、过孔和矩形铜填充，构造分层接触图，辅助发现支持模型中的连通与分离关系。**它不是完整 DRC、短路判定、真实铜面连通证明或制造验收。** UI 按钮和工具均使用“受限铜层几何分析（非 DRC）”命名。

真实样例 `PLACED.PCB + DEMO.NET` 的 C++ CLI 和实际 UI 结果：

- 铜对象：430；视口无关的候选比较：5211。
- 存在尚未覆盖的几何；本次未触发数量、比较次数或时间限制。**未触发资源限制不代表几何覆盖完整。**
- 88 个网络均为 **“无法确定”**，connected=0、separated=0、indeterminate=88。
- 模型内产生 21 组**跨网铜接触候选**。这不是 21 个已确认短路；清单需结合布局/未覆盖几何和原程序判断。
- 例：GND 有 53 个映射焊盘，支持模型内分成 50 个明确组/50 个可能组；因未建模图元及覆盖不完整，不据此断言断路。`+12` 支持模型内为 2 组，但同样标记“无法确定”。

上述计数是按本工具公开的假设得出的结构诊断，不代表原程序 DRC 结果。当前本地 PCB 中有尚未恢复字形的铜层文字，因此**全部网络状态保留“无法确定”**，即使支持子集存在明确路径也不报告局部通过；明确/可能分组仍作为诊断数值保留。只有全板几何覆盖检查通过后，才会在受限模型内分类为“已连接”或“仍分离”，它们仍不是原程序语义或实际板上导通的证明。

## 几何模型与保守状态

铜模型沿用板图整数 mil 坐标，图层使用原文件中的 6 个铜层编号 **1–6**（顶层、内层 1–4、底层）。屏幕自由取点测量不参与本分析。

- 直线走线：真实线宽的圆头胶囊；同层带宽正面积重叠可形成确定图边。
- 圆/长圆和钻孔：内接多边形用于确定铜，外接多边形用于可能铜；当前每个圆周 64 边。更保守的外接尺寸及 `0.0001 mil` 边界带都只是算法边界，不是测量精度或制造公差。
- 铜层圆弧：按已启用象限分别建立扇环与圆头的内外包络，相邻象限通过实际接触合并；不连续象限不隐式连接。包络无法形成连续内接轮廓的细线大圆弧保持未知，详见第八阶段说明。
- 矩形焊盘/矩形填充：按当前已经验证的矩形边界处理。
- 有孔的 13 层多层焊盘及有效过孔：**假设为贯穿六个铜层的理想镀通筒**。不验证实际镀层、盲埋孔、钻孔工艺或层对。
- 按正面积交叠确定“明确接触”；仅外接轮廓有接触时进入“可能接触图”。两个图的连通分量共同用于保守区分“支持模型内连接”“支持模型内分离”“无法确定”。

任一情况会使相应网络保持**无法确定**，不以 `Separated` 代替未知：

- 网络节点缺失、重复标号/网络名导致歧义、跨网归属冲突，或未解释的 NETDEF 附加元数据。
- 铜层文字、9/10 平面、13 层不适用的几何，超出当前包络支持范围的圆弧、非矩形填充、当前不支持的焊盘外形、零孔多层焊盘等缺失或变体。
- 铜层走线带有尚未解释的第七附加字段（包括值为 0）；仍保留几何分组用于诊断，但不据此报告连接或分离。非铜层走线的该字段不影响铜几何覆盖。
- 图元数、比较次数或运行时上限被触发、几何退化，或者接触仅处于近似包络边界。
- 净表高亮只是焊盘归属标识，不会在板图上画出假想导线；系统也没有从走线中推导 NET 分配。

跨网接触检测记录**共享同一确定铜连通分量上被映射到多个网络的焊盘标号-引脚名和对应的一基板图焊盘序号**，用途是提醒人工核查。它不证明电气短路：连接器、NET 名、库/板实例和图形解释均可能存在尚未确认的差异。诊断工具只做只读报告，不修改文件。

默认边界：最多 4000 个受支持铜图元、最多 250000 对候选比较、10 秒几何构建/分析的软时间预算。预算在图元构建和候选批次之间检查，不是对单次 Qt 几何运算的硬实时中断；完整耗时还包括网表映射和报告生成。达到限制时 `coverage_complete=false`、`limit_reached=true`，本阶段全部网络保留“无法确定”。

## 界面与命令行

- NET 已载入时点击“**受限铜层几何分析（非 DRC）**”，或从“网络”菜单运行（画布旧式 **N→A**，现代快捷键 **Ctrl+Alt+C**），后台构建并显示每个网的状态、确定/可能分组、接触候选和限制。
- 可选“受限铜层几何分析（非 DRC）”在独立后台任务中运行。没有网络来源时不运行；文件/来源变更会清空过期结果。关闭期间完成的迟到任务不会恢复旧报告。
- 报告同时列出未覆盖图元的种类、序号、图层和源行；面板内双击或 Enter 可定位，隐藏图层不会自动开启。最多保留 200 条明细并报告总数；遇到运行资源限制，不声称已扫描全板。
- 运行结果和计算网表/板图 SHA-256 一起记录，避免把不同版本的结果混看。

先在开发 PowerShell 启用 Qt：

```powershell
& .\scripts\Enter-QtEnv.ps1
& .\build\release\pt-copper-check.exe `
    'D:\project\pt_renew\pt\PLACED.PCB' `
    'D:\project\pt_renew\pt\DEMO.NET'
```

JSON 输出含逐网的三态、焊盘数、确定/可能分组、资源限制与不完整覆盖原因，以及需核查的跨网接触候选。退出码：

- `0`：所有网表映射完整，支持模型未检出分离/不确定或跨网候选。**不等于 DRC 通过或制造可用。**
- `1`：输入参数、PCB、NET 或结构无法读取。
- `2`：支持模型检测到仍分离的网或跨网接触候选；候选不等于已确认短路。
- `3`：存在未覆盖几何、资源上限或其他无法判定的网络。

## 测试与交付

独立 `pt-copper-tests` 使用合成几何测试直线、转角/端帽、同层交叉、跨层隔离、孔洞、过孔、矩形填充、未知圆弧/文字/平面、未解释走线附加字段、相切边界、重复冲突、CLI 报告和资源上限；没有复制或写入原始板图。Debug 与 Release 七组测试均 **156 项通过、0 失败**（包含组初始化与清理）。最终 Release 在真实窗口中完成后台分析，画面实际显示覆盖不完整、88 个网络无法确定及 21 个接触候选组；原目录 99 个文件摘要未变。

发布目录已重新部署，并核对 `dist/pt-renew.exe` 与 Release 构建文件的 SHA-256 一致。在移除 Qt SDK PATH 的环境中，以隔离副本启动发布程序，通过实际窗口按钮完成分析并检查截图；移除外部网表后，报告、节点列表和网络高亮清空，分析按钮禁用，板图保留。

这仍是**研究用只读分析**。下一步应恢复铜文字与平面语义、以单图元原程序样例验证层/接触规则，人工审阅候选组，并按 NET 语义补齐连接声明；在原程序 DRC 或真实板图提供独立地面真值之前，不应将任何“支持模型”状态用作工程放行依据。
