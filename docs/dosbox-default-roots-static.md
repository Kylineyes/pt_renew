| U4 | U3 结束且 `Uflag=0` | `835fec/835ffc` 清文本及清 F，之后去最终显式列表；若 `Uflag≠0` 则跳过这次清理 |
| U5 | `Uflag=0 且 Q=0` | `835da0` 直接跳最终显式列表，不执行 U1～U4 |

因此，`D=1,Uflag=1` 仍可能通过 U1 加载用户文件；`D=1` 不是贯穿整个启动函数的“所有用户读取禁令”。同样，`Uflag=0` 不能排除 A1，或目录偏好分支中的 R／UV 调用。U1 成功后不走 U4 的清理，是读取分支上的明确差异，不能将“最后会清一次”套到所有路径。

## 最终显式列表与八个默认候选

`836011` 开始再次遍历 E：每项先检查原名的文件状态（`4fe7b0`），状态为 0 时可经 `4fe830` 作当前 Windows 代码页转换并更新该元素；这是路径预处理接口，不是配置解析成功。然后 `8360ac` Parse(E[i])，**只在本次 AL=0 时**构造 `Uroot + E[i]` 并在 `8360e4` 重试。拼接没有绝对路径例外守卫，不能假定绝对 E[i] 会使前缀自动失效或被规范化移除。

此最终显式循环不检查 D，也不因累计 F 已非空停止；每项都按自身返回值决定前缀重试。它发生在上节 cwd 决策之后，因此相对 E[i] 的原名尝试相对当时 cwd，未必相对 C0。`-eraseconf` 的成功后删除支路另受 `+0x186` 控制，不改变这里记录的尝试顺序。

**只有显式循环结束后，`83620d/836214` 才用 D 决定是否整个跳过以下默认块。** D=0 时先在 `836222` 取 C1，再在栈 `+0xb30..+0xc10` 以 0x20 步长构造八个字符串；`8365a1` 从首项开始，`836623` 以 `+0xc30` 为终点，完整顺序如下。表中“前项未成功”均精确指每次回到 `8365b0` 时 `F=∅`，不是用日志有无推断。
