# 最新心跳超时的上传边界与资源复用评估

本阶段完成纯离线分析与资源寿命模型，结论是：**值得继续实现“每个不可变图层各自复用内存DC／DIB及像素”的最小实验，但现有证据不能证明其能修复心跳超时。** 没有Win32适配器、服务加载入口或新现场结果。稳定产品/dist仍为0.10.0，控制稳定性、固定0.11.0及NET／铜完整竞争仍未通过。

工作分支`feat/control-upload-offline-analysis`从`dev=e5340a3`建立。全程只读现有源码/JSONL及运行假API测试，没有启动GUI、控制服务、钩子、截图、输入或接续旧Pi会话。最新现场及父审计入口见[初始激活报告](control-initial-activation.md)。

## 最小实验的收益范围

原`_Layer`在构造时保存不可变BGRA，`set_opacity`只改变整窗透明度；每次仍重新获取屏幕DC、创建内存DC与DIB、复制像素、SelectObject、UpdateLayeredWindow并释放。本次超时区间没有重建图层阶段，允许评估已存在图层的后续上传。

| 可减少的API集合，仅限同一图层寿命内后续上传 | 首次过期前的集合占时边界 | 最后过期前的集合占时边界 |
| --- | ---: | ---: |
| CreateCompatibleDC/CreateDIBSection/SelectObject/DeleteObject/DeleteDC | 0.2966989～0.3121039秒 | 0.3121039～0.4326451秒 |
| 上述集合加memmove | 0.5585176～0.5739226秒 | 0.5891344～0.7100991秒 |

这些是旧调用路径内API包装的墙钟占时，包含调度与诊断；**不是预计节省量、CPU占比或充分修复条件**。移除调用会改变调度、资源常驻及新路径开销，不能直接从旧年龄减去该集合占时宣称通过。GetDC/ReleaseDC、UpdateLayeredWindow、显示器枚举、消息泵与整轮完成后的心跳/显示确认均保留。

推荐先做每图层独有的不可变surface，不按HWND或尺寸建立全局缓存，不把屏幕DC长期保留。以完整寿命内N次上传计：

| 操作 | 原路径 | 离线模型 |
| --- | ---: | ---: |
| GetDC / ReleaseDC，各自 | N | N+1，模型准备资源另有一次 |
| CreateCompatibleDC / CreateDIBSection / memmove，各自 | N | 1 |
| SelectObject | 2N | 2，首次选择及退役恢复 |
| DeleteDC / DeleteObject，各自 | N | 1 |
| UpdateLayeredWindow | N | N |
| API调用总数 | 10N | 3N+9 |

模型未合并首次准备与首次上传的DC使用，明确计入额外一次GetDC/ReleaseDC。调用数量变化不代表性能倍率；常驻DIB与内存DC的额外资源预算必须在接入时记录。

## 资源寿命模型及未完成条件

新增[资源模型](../tools/control_bitmap_surface_model.py)只接受注入后端，没有ctypes、Win32适配器、安装入口或serve开关。固定尺寸、不可变bytes及单一目标由构造参数绑定；复制后不保留可变像素指针。调用与释放必须在创建线程完成，失败不能继续present，允许重试清理剩余资源。构造尚未返回且清理也失败时，异常的`pending_surface`携带待退役实例，调用方必须保留并交回所属线程清理，不能丢弃该异常后继续创建新资源。

| 路径 | 模型已验证行为 | 运行时接入还须完成 |
| --- | --- | --- |
| 部分初始化失败 | 逐项注入GetDC、内存DC、DIB、选择、复制、ReleaseDC失败，回收已获得资源 | 原生返回0/HGDI_ERROR、DIB句柄成功但bits为空、错误码保留及部分结果移交 |
| 正常上传 | 透明度/位置变化保留原始像素，逐次完整update，屏幕DC逐次释放 | ctypes签名、BGRA/alpha、真实图像和窗口绑定 |
| 上传失败 | 原错误传播、立即退役，不重新上传或回退重试 | 原控制器error/failed锁存与收尾链对接 |
| 恢复选择失败 | 先删除DC解除选择，之后才允许删除位图；错误仍报告 | Win32返回值检查及实际释放证明 |
| 恢复选择与DeleteDC同时失败 | 保留仍被选中的位图/DC，禁止DeleteObject，所属线程重试退役 | 退出时未释放句柄必须报告，不能清零冒称成功 |
| 关闭/重建/同尺寸新目标 | 先退役旧实例，新实例分配新句柄，不借用旧目标资源 | `_Layer.close`在HWND销毁前退役；显示器变化/模式切换/线程结束时完整清理 |
| 线程或输入无效 | 调用后端之前拒绝 | 真正线程生命周期、重复启动与进程退出集成 |

后端契约是失败抛异常，失败操作的资源是否已释放由适配器规范化处理。模型不等于验证了所有原生失败返回值；不能直接将此模型接到真实窗口就宣称验收完成。显示器几何或模式变化时必须沿原代码关闭并重建全部相关surface；首次实验可对显示器变化保守整体退役，不缩减枚举来掩盖变化。

新增18项定向测试（上传分析8项、资源模型10项），加原61项，共**79项全部通过**。覆盖时间戳延迟、边界裁剪、API预算上下界、心跳排除更晚上传、嵌套并集、损坏输入拒绝，以及资源平衡、异常、关闭重试、跨线程与重建。没有真实GUI/Win32性能覆盖。本机原安装77/隔离77及稳定22/固定23/实验22的完整文件集合与摘要均与最后有效现场相同。
