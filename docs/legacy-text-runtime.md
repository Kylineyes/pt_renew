# 原文字形运行对照步骤

本步骤接续 [原文字形静态证据](legacy-text.md)。当前仍未确认原程序载入研究样例，所有笔画结果均为静态推导，`runtime_verified` 保持 `false`。

## 输入与方向字段

先复用 `.local-analysis/verification-11/runtime/pt/` 和 `dosbox-text.conf`。启动前核对隔离副本的 `PT.EXE`、`TRAXEDIT.OVR`、`GRAPH.DRV` 摘要及样例摘要；配置只能挂载隔离目录。保留既有输入和配置，新增样例使用不同文件名，并记录实际加载文件的摘要。

**内部解释器方向位与 PCB 文件方向字段的映射还需验证。** 当前 Qt 读取器只接受文件方向值 `0..3` 和 `16..19`；这只是重建程序的支持范围，不能证明原程序的完整接受范围。既有九组 `TEXT.PCB` 中包含文件方向值 `32`，不能仅凭内部解释器支持 `0x20` 就认定该记录能载入或产生 Y 镜像。

因此先使用方向值 `0` 的独立文件建立载入证据，再逐项检查其他方向。若文件被拒绝、字段被归一化或对象属性与请求不一致，应单独记录；不能将载入问题当成笔画解释差异。Y 镜像及组合需要先核对文件读取路径或原程序实际保存的字段，再决定其文件输入。

## 样例顺序与判据

每个文件只含一条文字，文字原点固定为 `(2000, 2000)`，笔宽 1、图层 1；11 层提供十字原点及非对称尺标。比较时记录两层是否可见，截图保留尺标和应用状态，不用文字自身的外观反推原点或比例。

| 顺序 | 输入 | 需要回答的问题 |
| --- | --- | --- |
| 1 | 单字符 `A`、`F`，高度 240，方向 0 | 文件是否实际载入；字符、位置、高度、图层及方向属性是否符合请求 |
| 2 | 同一视图中的原点、尺标和字符 | 坐标轴方向、像素比例、笔画端点、交点及可见边界是否与静态推导对应 |
| 3 | `AA`、`A A`、单个空格，高度 240 | 第二字符起点、空白移动是否一致；纯空格须结合属性或后续字符判断，空白画面不足以证明载入 |
| 4 | `A`、`AA`，高度 251、252，与 240 对照 | 静态整数缩放分别为 20、21；同视图下是否出现预期的保持与变化 |
| 5 | `F`，文件方向候选 `1..3`、`16..19` | 非对称笔画和原点的对应关系；逐项核对文件方向到内部旋转、镜像的映射 |
| 6 | Y 镜像和旋转、双镜像组合 | 映射有证据后再构造输入，逐项核对变换顺序 |
| 7 | 同一对象改变视图缩放、笔宽 | 何时进入替代路径，线宽及像素边界如何变化；与中心线比较分开记录 |

比较端点时先用尺标建立板坐标到画面坐标的关系，包含画面 Y 轴方向和视图平移。线宽、像素取整、裁剪或替代显示可能改变可见边界；保留测量值和残差，不以形状相似或随意的像素容差宣布一致。样例推导使用内部方向值时，须明确记录文件字段映射是已验证还是假设。

每次观察记录输入 SHA-256、原程序与驱动 SHA-256、配置、实际加载证据、对象属性、缩放、可见层、截图路径、静态请求参数和差异。分别标记“已观察”“推断”“未知”；截图、笔画导出、原字节和反编译结果只留在被忽略的本地目录。画面一致也不能证明运行时字体指针从未变化或铜面积已经恢复。

## 本轮准备与阻塞

`research/legacy-text-runtime` 分支重新探测 Windows-MCP，`Snapshot` 返回 `USER_CONTROL`，状态为 `user`、generation 2，没有取得截图。本轮没有启动 DOSBox，也未发送桌面交互或改用其他桌面入口。按用户约束保留阻塞，原程序实际加载、单字符对照和全部变换验证继续未完成。

本地 `.local-analysis/verification-12/` 保留桌面返回、摘要检查、准备脚本和 16 个独立 PCB 样例及其静态推导。样例覆盖表中前五项所需输入，每份清单明确标记文件方向映射未验证、运行未验证；Y 镜像及组合没有作为已确认文件编码加入。这些文件尚未复制到运行目录或交给原程序加载。

99 个原始文件的集合及 SHA-256 与既有基线一致，隔离副本三项二进制及既有 `TEXT.PCB` 与留存输入一致。当前仅更新研究步骤，Qt 渲染和铜层分析仍沿用既有证据边界。
