# 逆向结构分析与首阶段架构

日期：2026-10-21。实现分支：`feat/autotrax-command-shell`。

> 本文记录第一阶段设计与验收。第二阶段已加入真实图元只读预览和后台读取，最新字段覆盖、限制与模块说明见 [PCB 只读预览](pcb-readonly.md)。

## 1. 原程序结构：事实与推断分开

### 已观测的模块边界

| 原文件 | 已观测事实 | 重建边界 |
| --- | --- | --- |
| `PT.EXE` | DOS MZ 主程序，启动 AUTOTRAX 1.57 | 应用生命周期、命令调度、常驻运行时 |
| `TRAXEDIT.OVR` | 外置 `TPOV` 覆盖模块，包含编辑器相关字符串 | 编辑业务；具体函数职责仍待确定 |
| `TRAXEDIT.MNU` | 17 个一级入口，438 个菜单/对话框分段 | 命令目录、菜单与属性编辑入口 |
| `TRAXEDIT.KEY` | `KEYMACROFILE`；F1/F3 等展开为多步菜单按键 | 旧按键序列、命令映射、后续可录制宏 |
| `TRAXEDIT.DFT/.PAD` | 默认配置及焊盘设置；DFT 含历史绝对路径 | 用户配置与默认参数，不能照搬路径 |
| `GRAPH.DRV` | 与 VGA640 驱动完全一致 | 用 Qt 绘图层替代 DOS 显卡操作 |
| `.PCB` / `.LIB` / `.NET` | 板图文本、封装库二进制、网表文件 | 文件适配层；三者不混成一个解析器 |
| `TRAXPLOT.EXE/.OVR`、输出 `.DRV` | 配套绘图模块及输出驱动 | 单独输出服务，不在画布中直接实现 |
| `NETCHECK`、`PCB3CON`、`PCBTODXF` 等 EXE | 配套检查与格式转换程序 | 独立服务，按需求逐步重建 |

这些是外部模块、菜单和运行观察形成的功能划分，不是已恢复的原始源码类结构。

### Ghidra 静态结构探测

对未修改的 `PT.EXE` 使用 Ghidra 12.1.4、`x86:LE:16:Real Mode:default` 自动分析：

- 约 10 秒完成，未触发 120 秒分析超时。
- 识别 **910 个函数**。
- 建立 **45 个 CODE 内存块**，另有未初始化 DATA 与 HEADER 块。
- 代码块命名是加载器/分析器产物，不等于 45 个原始源码模块。
- 这次按已定义字符串数据筛选的目标字符串锚点为 **0**。二进制原始字节中存在相关字符串，但不能据此声称已恢复其函数引用；需进一步处理 Pascal 字符串与段地址。
- 没有加载 `TRAXEDIT.OVR` 中的覆盖代码；910 不是完整产品的总函数数量。
- 未完成函数语义命名、内部数据类型恢复或自动布线算法重建。

可复现的边界记录：主程序摘要见首次调查文档，本地结果在被忽略的 `.local-analysis/ghidra-structure.json`。

## 2. 菜单与快捷键模型

原一级入口及字母：

| 字母 | 原入口 | 新版中文入口 |
| --- | --- | --- |
| B | Block | 块操作 |
| C | Current | 当前参数 |
| D | Delete | 删除 |
| E | Edit | 编辑 |
| F | File | 文件 |
| G | Grid | 网格 |
| H | Highlight | 高亮 |
| I | Information | 信息 |
| J | Jump | 跳转 |
| L | Library | 封装库 |
| M | Move | 移动 |
| N | NetList | 网络 |
| P | Place | 放置 |
| R | Repeat | 重复 |
| S | Setup | 设置 |
| U | Un-Delete | 恢复删除 |
| Z | Zoom | 视图 |

`Repeat` 和 `Un-Delete` 在原主菜单中的精确调度方式还需运行时确认；新版先保留入口，尚未实现的业务禁用并明确标识。

### 一个命令，多种入口

每个命令具有稳定 ID，例如 `file.inspect`、`view.zoom_in`、`place.track`。命令描述、可用状态和快捷键集中在命令目录；界面为同一 ID 复用同一个 `QAction`。

- **顶部菜单栏**：鼠标直接访问 17 个入口。这里指窗口顶部菜单区，不通过自绘标题栏干扰 Windows 原生拖动和系统按钮。
- **现代键盘操作**：Alt+F 等菜单访问键，Ctrl+O 等命令快捷键，菜单内字母与方向键、Enter、Esc。
- **旧式单字母唤出**：只有画布获得焦点、没有修饰键时，F/P/N 等才打开对应菜单。以 F→L 对应文件加载入口。
- **文本输入保护**：不在 QApplication 上无条件拦截字母；文件名、搜索框、属性编辑框内的字母仍作为文字输入。
- **兼容功能键**：先支持 F5/F6 缩小/放大、F9 重绘、F10 居中。未实现的 F1 放焊盘/F3 放走线不能伪装成可用。
- **编辑状态机**：后续放置/走线工具通过命令切换活动工具，Esc 取消；不将连续走线流程拆成互不关联的 QAction 回调。

## 3. 新版分层

```text
src/
  main.cpp                    应用入口
  application/
    CommandCatalog.*          命令、菜单、快捷键定义
  domain/
    DocumentInfo.h            首阶段只读文件探测结果
  io/
    LegacyPcbInspector.*      旧 PCB 头、边界、摘要和标记行探测
  ui/
    MainWindow.*              菜单、状态、文件信息面板与命令派发
    BoardCanvas.*             视图缩放/平移/网格与画布焦点按键

tests/
  ShellTests.cpp              命令目录、文件探测与真实 GUI 事件测试
```

依赖方向：文件探测层只依赖 Qt Core；命令目录不依赖 Widgets；界面使用二者。不让文件适配层弹对话框，不让图形绘制反过来决定板图文件格式。

后续按真实功能增加：`BoardDocument`、整数物理坐标/单位类型、图元及层模型、可撤销编辑命令、活动工具状态、空间索引、LIB/NET 适配、DRC、布线与生产输出。没有业务需要时不预先堆积空服务和抽象接口。

## 4. 第一阶段的具体范围

### 实现

- 可构建、可启动的中文 Qt Widgets 主窗口。
- 17 个顶部入口与集中命令定义；实现单字母唤出及 Alt 访问，已实现命令共享菜单和快捷键入口。
- 空白二维工作区的缩放、平移、网格显隐、居中和重绘。
- **只读文件信息探测**：支持识别 `PCB FILE 4`、检查 `ENDPCB`、显示文件名、大小、SHA-256 和已知标记行计数。
- 探测采用大小上限，拒绝不支持的头、缺失结束标记及读取失败；不写入源文件。
- 标记行计数明确不是完整格式解析。文件信息面板提示“未解析和显示图元”，画布不会伪装成已经加载原板图。
- 禁用保存、编辑、DRC、布线、生产输出等尚未实现业务。

### 不宣称完成

第一阶段不是完整 PCB 编辑器，也不是已完成的只读板图查看器。没有图元渲染、库解析、写入、撤销、布线或输出。先把菜单、命令与输入结构做正确，后续逐步填充业务。

## 5. 后续填充顺序

1. 用原程序生成单图元 PCB，验证 FT/FP/FV/FA/FS/FF 及元件内部记录的字段，确定坐标单位和精度；编写格式测试，再加入只读渲染。
2. 研究 LIB 索引和图元数据，完成封装浏览、选择与放置。
3. 引入活动工具、选择/命中测试、撤销重做及保存安全策略，完成基础编辑。
4. 网表、连通性、测量与 DRC；每条规则对照原程序样例验证。
5. 需要行为等价的布线与生产输出再定向逆向，分别建立输入/输出回归测试。
6. 每一阶段独立分支、构建测试、GUI 验证后合并到 dev 并推送，由用户将 dev 合并到 main。

## 6. 桌面操作工具

本会话最初没有 Computer Use/MCP 桌面工具。已安装 Windows 原生的 **Windows-MCP 0.8.8**，其公开来源为 <https://github.com/CursorTouch/Windows-MCP>，并在当前项目本地客户端配置注册 `windows-desktop`。

- 这是 Windows 桌面操作 MCP 工具，不是把 Anthropic 的 Computer Use API 当成独立可安装软件，也没有在项目中加入 LLM 调用。
- `ANONYMIZED_TELEMETRY=false`，禁止工具默认遥测；未安装开机任务、未开放远程 HTTP 端口。
- 默认 DXCam 抓屏在本机返回黑图，已将项目本地注册设为 `WINDOWS_MCP_SCREENSHOT_BACKEND=pillow`，随后截图正常并已实际查看。
- 客户端健康检查已连接。当前已有会话的工具列表不保证动态刷新；必要时通过本地 stdio 客户端调用已安装服务器，重启会话后可直接加载注册工具。
- 截图与输入仅用于本次启动的目标窗口；尽可能限制截图区域，不采集无关桌面内容。

## 7. 首阶段验收结果

- Debug 与 Release 均构建成功，CTest 均通过；QtTest 报告各为 **18 项通过、0 失败、0 跳过**（含初始化与清理）。报告保存在各自构建目录的 `shell-test-results.txt`。
- 自动化验证覆盖：17 个一级菜单、单字母唤出、Alt+F、文本框输入不被抢占、菜单与 Ctrl+G 共享同一命令、缩放边界、只读输入不变、非法文件头/截断/二进制/超限文件拒绝、失败后的界面状态与未实现命令禁用。
- Windows-MCP 实际点击顶部文件菜单、从画布按 F 唤出同一菜单、按 Alt+F 访问菜单、按 Ctrl+G 关闭网格，已查看对应截图。
- 通过实际桌面按键验证 F→L 与 Ctrl+O 均打开原生文件对话框，然后取消；未执行写入。第二次对话框的可访问性树提取曾出现短暂 `UIA_E_ELEMENTNOTAVAILABLE` 重试，截图和按键流程仍完成，不将这个工具告警当作应用错误或全工具兼容性证明。
- 实际以只读方式探测 `PLACED.PCB` 和 `660A.PCB`，所示摘要与前期调查一致；原安装目录的 99 个文件再次逐一核对 SHA-256，全部未变。
- 已用 `windeployqt` 生成被忽略的 `dist/`；在清除 Qt/开发工具 PATH 的子进程环境中启动 `dist/pt-renew.exe` 成功，并查看了第二个样例的文件信息。该验证仍使用当前已安装 VC++ 运行库的开发机器，不是干净机器验收。
- 本阶段不宣称已能显示原板图、编辑或保存，也未完成 Windows 10 实机验证。
